## 已完成的软件保护，不等于迁移完成

Read Pico的真实`photoframe_app_main`先调用不允许擦除恢复的NVS初始化，再只读加载配置；失败直接返回，在板级、SD、显示和网络初始化前停止。独立integration入口仍不调用这个函数。主机加载测试用真实`config_manager.c`和NVS替身，未访问设备配置。

便携`config_read`只把NVS_NOT_FOUND当作允许使用默认值的情况。命名空间/已知键读取错误、类型不符、超长或非完整终止字符串、越界布尔/枚举/整数及无效/会被静默丢弃的cron规则使加载失败。密码读取失败不启动无认证Web，证书读取/分配失败不退化为未配置证书的下载；证书读入≤4096字节且两次长度必须一致。缺失配置默认值完整初始化，新板默认为必需的SD来源，不因“尚未挂载”被当作MemFS/URL板。

旧interval→cron仅在RAM预览，保留原interval和quiet-hours键，不自动写cron、删除旧键或提交NVS。有效0/180方向值原样读取，缺失才用新板180°默认；**读取成功不证明旧方向值与新native映射相容**，不静默重写用户覆盖。显式用户保存API保持原契约；仍须审查其他模块的配置读写、失败/并发和自动行为，不能把本加载保护推广到全部NVS消费者。

原板保留旧迁移/清理和密码读错误策略，另有真实源码回归。新板启动加载是单线程初始化契约，不是运行时并发重新加载或多键原子配置事务；字符串结构/类型验证也不代替网络地址、POSIX时区、DER证书等所有语义验证。

NVS报告NOT_FOUND不能单凭此接口区分“原本未配置”与“底层已丢失该键”；没有经批准的schema/版本及凭据存在性记录，不能宣称识别所有掉电损坏。缺失HTTP密码仍沿用上游认证关闭的默认行为，产品开放前须确认这一配置及网络暴露范围，本轮不开放Web或新建认证标记。

## 迁移前必须确认的配置

只按锁定PhotoFrame源码列出消费位置，尚未读取设备上是否存在这些值；未知Demo命名空间、厂家校准键不删除或猜格式。若需要实际清点，应单独批准只读导出和私有保存范围，输出类型/长度/存在性/错误，不公开凭据值。

| 配置组 | 真实业务影响 | 迁移/验收要求 |
| --- | --- | --- |
| `disp_orient`、`disp_rot_deg` | EXIF之后的逻辑输出方向/GUI旋转 | 人工确认有效覆盖是否保留，真机方向测试；不套用诊断无NVS默认结果 |
| `wifi_ssid/wifi_pass`、HTTP密码/访问token/自定义头、CA | 自动连接、设备访问权限和URL认证/TLS | 确认沿用旧网络还是重新配置；错误禁止默认放开权限，不记录值 |
| auto-rotate、cron、legacy interval/quiet-hours、来源/URL/相册/index | 自动下载、SD选图、时间和刷新 | 比较旧静默时段与RAM预览；初始化不改存储，批准前不自动轮播 |
| deep-sleep、debug、HA、配置同步时间 | 休眠、日志写入、远端请求/配置推送 | PMU睡眠未验收不启用；另审日志和远端配置消费者 |
| `.current.lnk`、`last_image`及旧current/暂存文件 | 当前预览、恢复显示及空间占用 | 不按名字删除照片；旧截断链接/原位写入的掉电恢复仍待设计/验收 |

## 分区冲突：不能直接使用上游全套烧写参数

以下旧布局来自已核验设备表和[固定factory CSV](../boards/partitions.read_pico_factory.csv)；上游布局来自[分区生成器](../scripts/generate_partitions.py)，不代表已经写入设备。

| 当前保护范围（半开区间） | 默认上游布局的冲突 |
| --- | --- |
| NVS `[0x9000,0xe000)` | 上游扩大到`0xf000`，其多出的页覆盖旧PHY |
| PHY `[0xe000,0xf000)` | 上游改到`0x11000`，不能直接沿用旧地址或内容假设 |
| factory `[0x10000,0x410000)` | 上游otadata `[0xf000,0x11000)`及coredump `[0x12000,0x20000)`与旧应用重叠，ota_0也从旧factory内部开始 |
| 内部FAT `[0x410000,0x910000)` | 默认OTA或LittleFS布局不保留原FAT范围与类型；外部SD不是这份内部数据的备份 |

16MiB容量和当前表已核验，未列分区的高地址区域**不能因此断言为空或可直接覆盖**。后续可以评估“保留NVS/PHY/factory/FAT，在高地址增加较小OTA槽”的专用布局，或批准重整布局；本轮没有选定、生成或接入新的活动分区方案。保留旧应用地址也不证明它能担当自动恢复固件。现有完整应用副本不包含全部Flash、CW32固件或校准；早期放弃完整备份不是对新迁移的授权。

## OTA暂时禁止运行，第一阶段最终要求仍保留

Read Pico `ota_manager_init`只提供当前构建版本和“迁移/镜像兼容未验收”的状态；检查/升级返回NOT_SUPPORTED，不加载/写OTA NVS、不注册后台任务、不查上游release、不调用HTTPS OTA、不确认新应用有效或重启。原板OTA实现保留。当前factory表没有otadata/OTA槽，当前本机构建也未开启bootloader rollback；**设备原bootloader的回滚能力尚未由本轮读取或验证**。

这是临时安全门禁，不计OTA功能完成，不替代最终移植上游OTA架构。重新开放前需要：

1. 用户选择数据保留与备份/恢复方案，批准每个目标范围；分区/bootloader变更不能复用factory app-only许可。
2. 核验本机真实分区、旧数据、目标镜像chip/revision/MMU、实际长度、空间及擦除粒度；只以asset文件名或ESP32-S3匹配不足以证明板型/屏幕/BSP相容。
3. 明确本项目发布来源及板型/显示/分区/构建身份校验，禁止直接采用上游通用板镜像；现有上游API/asset命名策略尚不满足新板完整身份验收。
4. 新布局和boot选择/回滚恢复经过构建、受控烧写回读及真机失败测试；PENDING_VERIFY只能在约定验收后确认，不能沿用启动即取消回滚。
5. 配置/SD数据保持、网络失败/截断/坏镜像/空间不足、刷新并发和低功耗退出经过产品回归，再通过独立变更解除此门禁。

主机测试/编译/ELF符号检查只能证明软件保护与链接边界，不证明设备迁移、联网/TLS、重启持久性或恢复成功；实际结果见[验证记录](VALIDATION.md)。
