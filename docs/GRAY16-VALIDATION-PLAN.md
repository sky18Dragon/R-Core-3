本轮照片与预期对照：逻辑左侧应为40像素白边；灰条为u=40–631的16×37像素，棋盘为u=40–679的16×4个40像素格。18MHz照片仍显示灰条、实心黑块和细线从有效显示区左边缘开始，缺失预期白边；棋盘约前三格宽形成连续区域，之后恢复规则节距，与12MHz失败形态基本一致。黑白元素共同复现，所以不能仅归因灰阶波形或PCLK。高层framebuffer、厂家原生绘图、dirty范围和source回调边界均与预期一致；问题目前位于source回调之后，照片不足以确定DMA首段、LE、CKV/STV或物理gate中的具体根因。

优先假设来自固定扫描实现而非外部报告：物理高度684此前在renderer/LCD两处均上补到688，每相位有4条hold填充；源码又记录STV并不总能单独把截短扫描拉回gate 0。使用实际36相GC16表的纯CPU敏感性模型，在“每相位累积4行”假设下会把左白边污染，并把影响扩展到约140行，与失败照片量级相近。精确684行同图A/B已经消除可见几何异常，显著增强该关联，但模型没有模拟DMA/pin/gate模拟行为且硬件只验证一次，仍不把它表述为完整电气根因证明。

## 验证顺序

### A · 先取得相位实测和官方图案基准

1. 离线复现官方测试页的几何和颜色，使用实际厂家绘图；保留黑白参考块、棋盘、细线。灰条按官方整数除法：逻辑宽684，左右margin40，inner604，step37；16条总宽592，x=40+37i、y=176、h=240，右侧余12像素留白。不得误画成16条占满604或扩大到全屏。文字若不复用厂家字体须注明差异，灰条内部不加编号或抖动。
2. 同时保留现有全屏控制作为不同负载样本，分别执行，不把布局改变和时序改变混在一次因果判断中。
3. 外层增加有界相位时间记录：每相启动/完成、相间空档、实际完成相数、供数错误、预填和被跳过相数。ISR只记录时间戳和计数，刷新/退出后打印；无逐行串口输出。测量必须覆盖GC16，现有静态清白78帧日志不能代替。
4. 主机验证旋转后灰码、坐标、边界与原厂绘图一致；时间记录溢出/丢回调明确报告不完整。固件编译后实施单张图，记录实际相位分布与相同曝光照片。

### B · 单独验证GC16铺白条件

精确684行同图已经让A的黑白几何单次通过；随后同固件编号灰阶仍白偏，因此执行了B单变量。未改固件、gamma、VCOM、PCLK、waveform或电源退出策略：新启动静态清白并人工确认后，只执行现有`gc16-white`，人工确认仍为均匀白色；确认后再输出同一`gc16-gray16-labeled`。两张均36/36相、31°C、零软件错误，编号图几何完整，但约05–15仍难逐级区分；已拒绝并STOPPED。GC16全白预处理没有可见改善。

本启动先完成初始清白和人工全白，建立可信参考。固定画面、波形、时钟和退出策略，使用已有全白图案路径执行 `set_all_white → GC16 full`，成功后下电并人工确认，再从白输出同一编号图。这样只隔离“GC16白预处理”，仍不等同官方连续高压流程。

白预处理也必须使用可检查返回值，出错立即清理/结束；不能因看起来白就忽略软件错误。参考未知或上次图案失败时不直接伪造back_fb为白。

### C · 再验证官方连续操作的电源条件

B未解释异常，因此已执行`gc16-gray16-labeled-continuous`比较“GC16铺白后下电”与“铺白→绘图连续高压”。连续段固定两帧：输入先校验，一次锁/prepare/主动温度采样，第一帧失败不进入第二帧，第二帧结束即stop；高压轨没有等待人工回复。实机两帧/72相/31°C全部成功并关电，但照片约05–15仍趋白，连续条件无改善；已拒绝并STOPPED。

错误退出、电源状态、两帧计数和72相容量测试、固定IDF编译及单次真机均已完成。固定上游同步绘制仍在内部使用`portMAX_DELAY`且没有安全取消接口；本轮正常返回，未验证卡死恢复。官方8秒是idle期限，不冒充绘制超时。

### D · 有证据后再检查扫描与性能

前导保持相位跳过、LCD18MHz及存储120MHz/HPM分别单独验证。先依据A记录确认长时间发生在供数、相间还是扫描内部，并核验器件与HPM适配。以官方默认36相为基线，不通过gamma或换表掩盖问题。48相表只作为后续明确标注的独立对照。

精确684行诊断已按计划完成：renderer与LCD同步，两个6行bounce buffer构成12行周期并整除684；图案、36相表、factory VCOM、gamma、PCLK18MHz和电源流程不变。离线及单次硬件A/B通过。若后续复现几何异常，D的首选仍是跨相位边界同时记录STV、CKV、LE、XSTL/DE和PCLK，数清复位窗口与有效数据行；软件回调计数不能替代物理证据。当前不再为几何引入额外变量，先在同一候选下量化16码L*与重复性。

官方独立固件已在同机输出正常16灰阶后，D阶段获得了新的直接证据。官方构建关闭PM/DFS并固定240 MHz；项目显示诊断开启自动DFS却没有在EPDiy扫描期间持有任何PM锁。EPDiy兼容RMT直接使用ESP32-S3 APB默认时钟并绕过新版RMT驱动的锁，renderer供数也依赖CPU。项目已测的30.5–48.5 ms/相显著偏离11.2 ms求解值，且相间空档只有约22 µs；官方同机UI约399 ms/36相。当前首选单变量因此改为“刷新事务持有CPU max + APB max”，而不是继续更换波形、gamma或VCOM。

两把锁覆盖静态清白及prepare→draw→stop，失败路径同样释放，并记录加锁前后CPU/APB实频；310/310主机测试、20/20构建/控制台检查和固定IDF v6.1固件编译通过。候选305,104字节、SHA256 `6f2a4ea106f7aab2c1d8ff2fd2605f70b0aefafaa5c437b0d688106a12055255` 已app-only烧写并全长回读。真机得到11.090–11.112ms/相、36相399.327ms、HL draw 419ms，照片中心16阶中位数严格递增；时序与光学两个门槛同时通过。会话经pattern-confirm、stop、status安全结束，根因确认而非仅性能改善。

## 灰阶验收方法

- 固定屏幕方向、均匀漫射光、拍摄距离；固定曝光/白平衡，避开灯反射和过曝。记录环境温度、主动温度、供电及刷新结束后的拍摄间隔。
- 每阶中心取相同大小区域，避开边界和文字；保留0黑、15白作为参照。肉眼逐对记录0/1直到14/15是否可区分，不用“有16条”代替“有16级”。
- 同照片比较中心区域亮度/离散度与阶间顺序，只作为诊断；JPEG亮度不是校准反射率，不能设置任意阈值就宣称16光学等级通过。需要严格量化时使用灰度/反射率测量设备。
- 验收分开记录：灰码正确、扫描完整、16级单调与相邻区分、无异常条带/残影、复现稳定性。单张通过后才安排重复/照片链路，P2全部完成仍需原计划其他图案和连续验证。
- 结果分支：若布局改变有效，继续检查区域/供数负载；若GC16白预处理有效，检查起始光学状态；若连续电源有效，检查启停/稳定时间；若相位时间异常，先修复对应机制。每项都是待验证假设。

本方案维持PhotoFrame主架构、app-only布局与厂家校准边界。PM锁候选的烧写、回读、清白、唯一局部页、照片确认和安全退出均已完成；12条renderer/LCD供数关系与全部36相同样通过，不再需要为本次白偏继续改gamma、VCOM、波形、PCLK或追查物理gate。后续只按P2剩余范围验证重复性、其他图案、照片链路与长期稳定；任何新硬件轮次仍需重新建立本次启动的白参考。
