# 小纸 Pico 16 灰阶验证方案

日期：2026-10-04。目标：查明当前浅灰大面积接近白色的原因，验证实际灰阶区分能力。A阶段边缘供数扩展已app-only部署；人工白屏后唯一局部图36/36相、每相696次、12条目标行完整，六组成对轨迹相等且五边界可区分。但新实拍仍复现左侧宽连续区，本轮明确不通过，根因边界收窄到source回调之后、可见像素之前。已部署分析器误判已离线修正，未重新部署；会话STOPPED。B/C/D未执行，暂停进入B。

实施更新：A阶段已实现 `gc16-gray16-page`（ID8/位0x100）和GC16相位观察。图案保留官方灰条/黑块/空框/棋盘/细线几何，省略文字、页眉分隔线及菜单；保持官方inverted-portrait像素映射后恢复landscape。实际厂家绘图与独立便携参考逐字节比较。新增断言明确核对40像素左边距、37像素灰条和40像素棋盘节距。后续边缘扩展对逻辑u=0–127内12条关键行记录36相供数指纹，以同内容行配对和五个边界可区分作为fail-closed条件；普通及ASan/UBSan全量现各299/299通过。该图只能是本启动人工白参考后的第一张。

相位观察在注册、`epd_lcd_start_frame`入口、完成回调记时间，最多48条，当前期望36相；分别输出prepare/start-to-done/gap，保持原始行回调及返回值。边缘扩展仅在命中的12条行计算304字节脉冲指纹，不记录整帧；溢出、重启相、缺帧、同组错行或边界全程不可区分均不能通过。时间戳和指纹都是软件边界，包含观测开销，尚不能代替示波器/DMA/gate验证。本轮实机已完成单张：每相696次、目标行与边界关系通过；旧二进制把32帧×8次CPU1启动预填合并记作`wrong_core=256`。修正候选仅允许row0–7归入`core1_start_prefill`，其后CPU1回调仍失败；普通/ASan定向19/19、全量各300/300和固定IDF 6.1编译通过，未部署。具体证据见VALIDATION。

本轮照片与预期对照：逻辑左侧应为40像素白边；灰条为u=40–631的16×37像素，棋盘为u=40–679的16×4个40像素格。照片按右侧空框及正常棋盘格定标后，左侧连续区约112–120逻辑像素，表现为约前80逻辑像素与预期不符，u≈120之后恢复正常节距。黑白棋盘也复现同一异常，所以不能仅归因灰阶波形。高层framebuffer及dirty范围已排除预期裁切，问题目前位于framebuffer之后；照片不足以确定LCD/DMA/CKV/STV中的具体根因。

- [display.c](https://github.com/MindReset/read_pico_firmware/blob/28cde682a4468a581c278761922724f57d976418/main/display.c)：铺白使用 GC16 full；连续操作保持高压轨，空闲到期8秒下电；FULL扫描、预填32行。
- [波形定义](https://github.com/MindReset/read_pico_firmware/blob/28cde682a4468a581c278761922724f57d976418/components/e0470_epaper_waveform/include/e0470_epaper_waveform.h)：官方16灰按钮选默认裁剪GC16 36相；48相完整表是另一份对照，30相是8灰表。完整表“11级”注释并非本机测量，也不能据此否定产品16灰规格或降低项目目标。

最新已部署应用 `eea27432…`（284,688字节）已全长回读一致，分区不变。一次静态清白14.017秒，人工全白；一张厂家绘图控制完成2.346秒、32°C、native_equal=1，绘图/退出错误均0。该张尚无用户明确目视结论，未确认也未拒绝。随后stop/显示及HAL释放ESP_OK、完整STOPPED/drawn=0x80/confirmed=0，控制台正常关闭。旧无编号/编号图白偏失败仍有效。

## 验证顺序

### A · 先取得相位实测和官方图案基准

1. 离线复现官方测试页的几何和颜色，使用实际厂家绘图；保留黑白参考块、棋盘、细线。灰条按官方整数除法：逻辑宽684，左右margin40，inner604，step37；16条总宽592，x=40+37i、y=176、h=240，右侧余12像素留白。不得误画成16条占满604或扩大到全屏。文字若不复用厂家字体须注明差异，灰条内部不加编号或抖动。
2. 同时保留现有全屏控制作为不同负载样本，分别执行，不把布局改变和时序改变混在一次因果判断中。
3. 外层增加有界相位时间记录：每相启动/完成、相间空档、实际完成相数、供数错误、预填和被跳过相数。ISR只记录时间戳和计数，刷新/退出后打印；无逐行串口输出。测量必须覆盖GC16，现有静态清白78帧日志不能代替。
4. 主机验证旋转后灰码、坐标、边界与原厂绘图一致；时间记录溢出/丢回调明确报告不完整。固件编译后实施单张图，记录实际相位分布与相同曝光照片。

### B · 单独验证GC16铺白条件

当前不执行B。A的黑白几何已不符合预期，若此时加入GC16铺白会把起始光学状态和行映射问题混在一次实验中。先取得能区分逻辑行、renderer输出和物理gate落点的边缘定位证据，再由用户决定是否恢复B。

本启动先完成初始清白和人工全白，建立可信参考。固定A的画面、波形、时钟、退出策略，增加一次官方 `set_all_white → GC16 full` 白预处理，成功后下电并人工确认，再从白输出同一图。这样先隔离“GC16白预处理”，仍不等同官方连续高压流程。

白预处理也必须使用可检查返回值，出错立即清理/结束；不能因看起来白就忽略软件错误。参考未知或上次图案失败时不直接伪造back_fb为白。

### C · 再验证官方连续操作的电源条件

若B未解释异常，在与B相同的画面/参数下，比较“GC16铺白后下电”与“铺白→绘图连续高压”。连续段必须是有界事务：铺白错误立即停止，绘图后执行到期关电/退出；不得让高压轨等待人工回复。人工先确认事务起点白参考，结束后观察最终图；过程中GC16铺白属于事务子步骤，不声称用户逐帧确认。

该项需要先实现超时、错误退出和电源状态测试，再进行硬件验证。官方8秒期限可作为复现参数，不能只保留keepalive而遗漏idle_check，造成无限保持。

### D · 有证据后再检查扫描与性能

前导保持相位跳过、LCD18MHz及存储120MHz/HPM分别单独验证。先依据A记录确认长时间发生在供数、相间还是扫描内部，并核验器件与HPM适配。以官方默认36相为基线，不通过gamma或换表掩盖问题。48相表只作为后续明确标注的独立对照。

## 灰阶验收方法

- 固定屏幕方向、均匀漫射光、拍摄距离；固定曝光/白平衡，避开灯反射和过曝。记录环境温度、主动温度、供电及刷新结束后的拍摄间隔。
- 每阶中心取相同大小区域，避开边界和文字；保留0黑、15白作为参照。肉眼逐对记录0/1直到14/15是否可区分，不用“有16条”代替“有16级”。
- 同照片比较中心区域亮度/离散度与阶间顺序，只作为诊断；JPEG亮度不是校准反射率，不能设置任意阈值就宣称16光学等级通过。需要严格量化时使用灰度/反射率测量设备。
- 验收分开记录：灰码正确、扫描完整、16级单调与相邻区分、无异常条带/残影、复现稳定性。单张通过后才安排重复/照片链路，P2全部完成仍需原计划其他图案和连续验证。
- 结果分支：若布局改变有效，继续检查区域/供数负载；若GC16白预处理有效，检查起始光学状态；若连续电源有效，检查启停/稳定时间；若相位时间异常，先修复对应机制。每项都是待验证假设。

本方案维持PhotoFrame主架构、app-only布局与厂家校准边界。逻辑u=0–127的renderer/LCD供数探针已完成离线交付；下一步只有在用户明确批准新的app-only/清白/单张局部图轮次后才部署取证。若12条行关系正确而实屏仍错，问题收窄到回调之后，仍需DMA/CKV/STV/物理gate证据；若供数关系失败，则先修软件行序，不恢复B。本轮没有新增烧写、清白或GC16。
