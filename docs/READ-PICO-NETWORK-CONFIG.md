## 保存与读取

Read Pico 名称检查非空、最多63字节及ASCII控制/DEL字符；不截断，允许其他字节，但不等于UTF-8或mDNS完整语义验证。检查NVS open/set/commit，关闭后才发布内存；兼容void接口也执行同样检查、失败记录而不发布。读取使用调用方持有的副本，容量不足或繁忙不改变输出。

网络组包含静态IP、掩码、网关、DNS及DHCP/static模式。便携 `wifi_network_json` 只解析已知网络字段，拒绝错误类型、超长值、未知模式和大小写等价重复键；缺失字段不更新。`wifi_network_patch` 在当前缓存副本上叠加选中字段，校验有效组合后才保存四个字符串及一个模式，共一次commit；只有确认后才一次发布整个内存组。

地址要求四段十进制IPv4，拒绝多位前导零，避免固定lwIP将它们按八进制解释。静态模式要求三个地址完整，DNS允许空串回退；DHCP允许保留未选中的旧静态字符串，但新选择的非空地址必须有效。不是连续子网掩码、同网段、单播或可达性保证。原板保留原解析/逐字段保存策略。

名称、网络组、配网保存、时区/NTP/revision及启动加载共用零等待控制，繁忙明确返回错误。配网仍先使用候选验证，确认保存才发布；不增加隐式驱动持久化。启动加载失败保留最后确认的名称和网络缓存。NVS set可能已改变存储，commit失败也不意味着回滚；SDK nvs_close为void，无退出错误或掉电原子性确认。

## 消费者与剩余限制

普通配置更新的网络参数统一形成候选，不再依次void写入后再检查模式。名称保存错误不继续更新hostname；已保存而mDNS或Wi-Fi hostname更新失败，明确报告部分效果、不报完整成功。Wi-Fi取网络组副本并校验后才改射频，hostname取名称副本后才交给SDK。配网保留DHCP静态值也先复制。

mDNS初始化/更新先复制名称，忙时不init/free；一次注册用同一副本。固定mDNS 1.14.0在hostname/instance/TXT接口复制字符串，栈副本不是异步借用。hostname等待内部动作但instance是排队返回；这些返回不等于实际广播/浏览器发现成功。保持上游可选photoframe服务失败非致命契约，未加入完整mDNS所有权/互斥/退出ACK。

配置GET、system-info、HA通知和在线启动日志已读取名称副本，GET读取网络组副本并检查这些新增JSON字段分配。每次副本读取独立受保护，**不是整个GET全部字段同一时刻的快照**。HA其他配置、其余JSON分配/响应、Wi-Fi凭据void接口及其他general字段仍待审查。

名称副作用支持同值重试；已将远端三个组及版本、本地general及版本、独立处理与调色板更新纳入共享应用控制，见下节。直接setter与全SDK生命周期仍待审查。不是CAS、失败回滚或P3/P5完成。

## 全组应用保护与请求诊断副本

远端一次解析/general→processing→palette→revision全程持有同一`config_apply_run`控制；general走私有值适配，不递归进入公共guard。本地general使用`config_apply_transaction`，apply失败不touch，touch失败保留applied/未finished结果，明确返回503部分效果说明。该公共便携协调器区分未接纳繁忙与已进入回调后返回INVALID_STATE，不把二者当同一状态。

本地general只有获得控制后才清理并快照自己的config/cert诊断，错误信息在释放控制前复制到调用方结果；HTTP返回不再consume共享缓冲。相邻远端应用清理旧诊断，繁忙请求不调用业务、不触碰活动诊断。Read Pico的general错误JSON分配/打印及响应返回也检查，成功使用固定JSON文本。保留旧板原保存与诊断策略。现有诊断写入调用均在该值适配内，但不承诺未来外部直接调用公共set/consume函数也受保护。

processing/palette的POST/DELETE经同一控制，包含接收、解析、保存、palette重载、touch和响应；busy仅发送一次503，已接纳处理器失败不追加第二份响应。GET使用共享应用控制捕获读取结果，不支持的方法不进入修改业务，原路由与认证保留。持有控制穿过SDK收发/保存不提供新的等待时限，远端可能因正在接收的本地请求直接返回忙，而不是排队或自动重试。

这不是NVS跨组原子性/回滚、整个GET快照、所有直接setter/启动加载/配网对应用级控制的完整覆盖，也不保证图像处理等独立palette消费者互斥。底层已接入的checked配置控制仍另行保护自己的缓存。处理/调色板HTTP完整接收、读取和响应检查已接入；其余general字段/凭据/语义、RTC/调度/文件/空间及完整退出继续。真实utils/HTTP整链未在主机执行，仅便携控制/真实解析器测试、源码接入检查及固件链接；ASan非TSan，未部署。

## 名称应用、重试与一般配置串行

`config_manager_apply_device_name_checked`在已有配置控制内复制名称，名字变化才检查保存；持有保护直至mDNS→Wi-Fi两个回调返回。回调接收同一独立名称，通过新增named适配入口直接传给SDK，不再递归调用检查式getter。保存失败不调用两服务；服务失败保留已确认缓存，仍标记网络名称未确认。下一次同值请求重试两个服务，不重复写入NVS；两者返回成功后相同请求跳过副作用。

确认状态仅本次启动内有效，不写NVS；启动/成功重新加载、显式名称保存与配网保存使其失效，失败加载保留原确认。`name_accepted`包括未改变的已加载/默认缓存，不证明物理NVS存在该记录。提供失败阶段与名称接受/服务返回确认，不假称SDK错误撤回已保存名称。已有mDNS正常启动不隐式标记两服务共同确认，因此第一次同值配置可能重新注册一次。

mDNS新增零等待注册/更新保护，重入忙不free当前操作，普通返回/失败释放保护；不证明所有权、SDK内部动作/广播或停止ACK。Wi-Fi named入口保留无线控制/返回检查，名称参数独立复制、检查形状；实际DHCP协商仍在下一次连接。名称事务持有配置控制期间，检查式NTP/TZ等读写会返回忙；不对SDK内部等待提供新超时保证，也不跨任务强制取消。
