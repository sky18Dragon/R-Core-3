# 库绑定日志与双快照格式（开发原型）

更新时间：2026-10-01。实现位于 `components/frame_core/frame_storage.c`。另有 [主机 POSIX 文件参考适配](FILE-STORE.md)，但仍不含设备 SD/Flash 适配或生产库迁移；不构成远端 ACK 的持久化证据。

## 库身份与提交

`frame_storage_init` 接受非零 16 字节 library-id。ID 必须来自经过核验的持久化库绑定，不得由挂载路径或随意生成的新值替代旧库身份；实际创建、保存和换卡确认流程尚待实现。

上层只使用 `frame_storage_import/action`，不得绕过包装层直接修改内部 catalog。每次成功提交增加全局序号；单照片 sequence 仍用于过期操作检测。提交回调收到完整 76 字节 PFJ1 包，必须完成适配层规定的同步后才能返回 true。任何不确定结果锁定写入，重新打开、扫描后判断，不能凭内存状态重试。

PFJ1 使用显式 little-endian：magic/schema/size/保留字段 8 字节，library-id 16 字节，全局序号 8 字节，PFR1 状态记录 40 字节，包 CRC32 4 字节。CRC 覆盖前 72 字节；同时验证内部记录 CRC 和保留字段。

全局序号不得回绕，耗尽后停止写入。所有操作仍要求单写入者串行调用，回调禁止重入；输入/输出缓冲不能与内部照片数组重叠。

## 快照

PFS1 是 48 字节头加 N 个 40 字节状态记录。头保存总长度、记录数、library-id、全局提交点、负载 CRC 和头 CRC。拒绝未知 schema、错误长度、重复照片身份、非法状态和容量超限；加载失败不修改目标 catalog。

该开发状态快照 5000 条占 200048 字节。这个数不包含照片元数据、强身份来源、源文件/缓存校验摘要和跨介质事务信息，不能替代技术方案中的最终空间预算。

双快照加载分别验证两个副本，选择全局提交点较高的有效副本；同序号不同内容返回冲突，不猜测哪份正确。加载器返回 -1 时，调用方必须停止打开库，不能把失败当成空库然后覆盖重建。

较新副本损坏时可以加载旧副本，但恢复最新已确认决策依赖保留的日志。写入流程必须：保留当前快照与完整所需日志 → 写另一槽并同步 → 重新读取校验 → 才更新有效槽记录。主机参考适配已实现两个槽都同步回读后才回收日志，设备端尚未实现。禁止仅凭一次 encode 成功回收旧数据。

## 日志恢复

支持两种输入：从全局序号 1 开始的保留日志；或从快照提交点 + 1 开始的压缩后日志。输入为一次完整、不可并发修改的日志缓冲，不是可任意分片追加的流式 API。

快照覆盖的旧包仍验证库身份、CRC 和连续性，但不重复应用。新包必须逐个连续，并通过 catalog 状态迁移校验。错库、跳号、重复、损坏或截断时停止在有效前缀，并锁定写入，不自动截断文件。保留日志若在快照提交点之前就结束，也锁定写入，防止就地追加造成断层。空日志可表示完整快照之后的空压缩日志，是否真实空文件仍由介质层核验。

## 验证与边界

测试覆盖：两个槽的先后顺序；新槽每字节截断/损坏后的旧槽回退及日志补齐；同序号冲突；错库；重复身份；容量不足；完整与压缩日志；全局序号断层；每字节日志截断/损坏；0–76 字节的不确定提交；5000 条快照编码和恢复。

另有主机 `tmpfile` + `fwrite/fflush/fsync` 日志往返测试，使用临时文件，不覆盖已有库。该测试不是正式文件适配器，也不能证明 FatFS、Flash 或 SD 控制器在硬件掉电后的可靠性。

主机参考适配已覆盖绑定文件、双槽写入/回读和日志回收。设备端尚缺：库绑定及换卡流程、源图/缓存事务、FatFS 双槽与回收映射、单写入任务、Flash 备份、跨介质补偿和真实故障注入。Demo 0 没有调用此模块。
