# 主机文件存储参考实现

更新时间：2026-10-01。源码：`host/frame_files.c`、`host/frame_files.h`；测试：`tests/test_files.c`。

这是 POSIX/macOS 主机参考适配，不是 ESP-IDF/FatFS 驱动。设备 Demo、Flash 备份、照片文件导入和相机通信没有变化。

## 打开与创建

调用方用 `FRAME_FILES_INIT` 初始化句柄，提供已有目录、预期的 library-id 和照片数组。create 只接受空目录（可以有锁文件），不创建目录、不删除已有数据；失败时保留已产生的文件作为证据，不自动重新创建。open 必须读到有效绑定、至少一份有效快照和存在的日志，禁止将损坏库当空库初始化。

文件固定为 `library.id`、`snapshot.0`、`snapshot.1`、`journal`、`writer.lock`。PFB1 绑定文件固定 32 字节，包含 schema、library-id、保留字段和 CRC。新建时先同步初始快照和空日志，最后写绑定文件并同步目录。

目录打开后使用 directory-fd 与 openat 固定相对目标，拒绝文件符号链接、非普通文件和多重硬链接；打开最终目录也拒绝符号链接。父目录链必须由调用方信任，这不是面对恶意文件系统操作者的安全沙箱。

`flock(LOCK_EX|LOCK_NB)` 持有整个会话的单写入者锁。锁是 POSIX 协作锁，其他不遵守该锁的软件仍可修改文件；所有函数仍须在同一任务中串行调用。

## 追加与恢复

追加前重新校验绑定文件，以及日志的长度、设备/inode 和当前目录中的名称关联。记录全部 write 完成并 fsync 成功才报告提交成功；发生不确定错误时锁写。源图尚未导入，因此这里的 import 仅表示状态身份登记，不表示已持久化照片。

open 读取有界快照并加载双副本，再恢复日志。损坏尾部可以打开有效前缀供只读检查，但不截断、不继续写入，也不能 checkpoint。两个快照均失效或绑定错误则打开失败。日志最多 4 MiB，超限文件拒绝打开；正常追加达到上限前返回 FULL，调用方可主动 checkpoint 后继续。

目前快照和日志缓冲在主机内存中读取：单快照最多 200048 字节，日志最多 4 MiB；不应直接沿用为设备内部 RAM 分配策略。

## 检查点与日志回收

严格顺序：编码当前状态 → 校验绑定和日志 → 写非活动快照、fsync 文件及目录、重新打开并逐字节核对 → 同样写活动快照并回读 → 两份都确认是当前状态后才 ftruncate 日志并 fsync 日志/目录。

非活动槽未验证前不覆盖当前有效槽；任一失败都停止并锁写，保留未被回收的日志。第二个槽失败时第一个新槽和旧日志可用于重新打开恢复。只有两份当前副本验证完成才回收日志，避免新副本损坏后旧快照没有必要日志。回收后的任何不确定错误仍锁写，交由重新打开决定状态。

这是基于 POSIX fsync 返回语义的参考顺序，不声称抗任意掉电/介质故障。没有实现 macOS F_FULLFSYNC；fsync、目录同步、flock、openat 等也不能直接假设适用于 FatFS。设备适配必须另做映射、单写入任务与真实断电注入。

## 已验证

- 新建、身份登记、用户决策、删除意图、检查点、日志回收及重新打开恢复。
- 同一目录拒绝第二个写入者；错库打开和已有库重建拒绝。
- 尾部截断/损坏保留原文件，只读恢复；两个坏快照拒绝打开。
- 单个快照损坏从另一副本恢复。
- 链接导致检查点第一/第二槽写入失败时锁写且保留日志，不覆盖链接目标。
- 会话中绑定变化、日志被替换、超大日志和非空目录保护。

测试只在 mkdtemp 创建的专用临时目录操作，清理固定测试文件，不访问或覆盖用户照片库。尚未做真实掉电、磁盘满和介质拔出注入。
