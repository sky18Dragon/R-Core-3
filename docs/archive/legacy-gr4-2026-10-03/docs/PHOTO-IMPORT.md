# 离线照片导入事务原型

设备进展（2026-10-02）：新增独立三图 JPEG 源落盘→设备解码／Cover→生成缓存→完整参考比较→本地索引诊断，主机和固件编译已通过，设备运行待验。尚未将下述正式 PFU1／PFI1 导入事务搬到板端，不将诊断 KEEP 当产品决策。见 [设备 JPEG 诊断](JPEG-CACHE-SAMPLES.md)。

更新时间：2026-10-01。对应 `frame_assets` 可移植核心、`frame_files_asset_io` POSIX 参考适配与 `frame_import` 主机工具；不是已接入设备的照片库或相机下载器。

布局更新：支持 layout=1 Fit／layout=2 Cover 居中等比裁切。显式 `frame_files_ingest_layout` 或 CLI source.jpg 后追加 `--cover` 导入 Cover；旧接口／无参数默认 Fit 兼容。恢复按 PFU1 保存布局，不混用；已登记 ID 不迁移／覆盖，不同布局的待恢复凭据冲突锁写并保留源。新增便携及 FatFS 只读缓存门禁，主机 21/21、v6.1 编译通过，未接设备显示入口／烧写。详见 [Cover 缓存](COVER-CACHE.md)。

## 提交顺序

原整缓冲 `frame_assets_import` 参考接口由调用者提供 JPEG 和缓存；其单写入会话顺序如下。当前 CLI 已切换下文流式路径，不再申请整张 JPEG 缓冲：

1. 检查 library-id、容量、源图 CRC、完整 JPEG 解码、缓存格式；任意已登记 photo-id 直接过滤，保留用户决策/tombstone。
2. 独占创建 `<photo-id>.intent`，同步、关闭、同步父目录并回读。
3. 独占创建 `<photo-id>.jpg`，同步、关闭、同步父目录并逐字节回读。
4. 独占创建 `<photo-id>.g4`，保存头与像素，同步、关闭、同步父目录并回读。
5. 重新检查产物和库绑定，通过 PFJ1 回调持久化 NEW，成功才发布内存索引。

文件名仅由外部确认的 16 字节 ID 构造，不接受任意相机路径。ID 不得用 CRC、文件名或 SD 路径代替。适配借用 writer.lock，检查库绑定、普通文件和单硬链接，拒绝符号链接；非阻塞打开避免误入 FIFO 后等待。锁要求合作写入者遵守，不是抵御其他进程恶意修改目录的安全边界。

本原型不使用 `.part` rename，不假设 FatFS rename 断电原子性。产物存在不代表可展示：需索引提交，未来显示端也需重新校验缓存。

## PFI1 / PFG1 格式

意图、源图恢复凭据与缓存头均为 80 字节，显式小端，禁止直接保存 struct。

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | 意图 PFI1 / 缓存 PFG1 / 源图凭据 PFU1 |
| 4 | 4 | schema = 1 |
| 8 / 24 | 16 / 16 | library-id / photo-id |
| 40 / 44 | 4 / 4 | 源 JPEG 字节数 / CRC32 |
| 48 / 52 | 4 / 4 | 缓存宽 / 高 |
| 56 / 60 | 4 / 4 | profile=1；layout=1 Fit／2 Cover 居中，无 ROI |
| 64 / 68 | 4 / 4 | 缓存像素 CRC32（PFU1 必须 0） / 字节数 |
| 72 | 4 | 保留，必须 0 |
| 76 | 4 | 前 76 字节 CRC32 |

PFG1 后跟按行打包的 4 bpp（左高半字节、黑 0 白 15；奇数宽度末尾半字节必须白）。1216×684 缓存为 415952 字节；旧 `frame_convert` 裸数据仅 415872 字节，不能冒充此格式。

CRC 不是密码学认证或照片强身份。核心校验尺寸、CRC、绑定；JPEG 回调必须完整解码。缓存确由该 JPEG 渲染的责任在管线，当前 CLI 从校验后的本地源图渲染；核心不能仅凭 CRC 推断图像等价。源图上限 8 MiB、缓存每边不超过 1216。默认解码/相机 XS 的 4 Mi 像素限制保持不变；本地文件显式缩放接口允许至多 32 Mi 源像素、每边 8192，原生 1/2、1/4、1/8 缩放到不超过 4 Mi 的灰度中间图。缩放边缘采用解码器向下取整，可能略去不足缩放块的末尾像素；3000×3000 样片在 1/2 下无这种尺寸余数。

## 当前流式路径

`frame_files_ingest` 面向可 seek 的本地输入，使用 1024 字节复制/CRC 缓冲。先预检完整 JPEG 与源大小/CRC，再写不可覆盖的 `<id>.source`（PFU1）→ `<id>.jpg.part`。随后完整解码校验暂存源，不申请整幅灰度图；独占复制成 `<id>.jpg`，同步关闭并再次验证，才申请灰度和展示缓存。为避免 rename 原子性假设，当前保留 `.part` 副本，尚无自动回收；每张图可能暂占双份 JPEG 空间。

渲染分配/生成失败返回 `FRAME_IMPORT_RENDER_PENDING`，源图与凭据仍在，但没有 NEW 索引或 ACK。这是由源产物和未提交索引派生的待渲染状态，并非已经完成产品级 RENDER_FAILED 错误记录。`frame_files_recover_photo` 只使用本库 PFU1 和源图；源成品缺失时可从完整 `.part` 补成品，再重渲染。`frame_assets_complete` 回调再次校验持久化源（长度/CRC + 完整 JPEG 解码），回读 PFI1/缓存后才提交索引。

源与暂存都缺失返回 SOURCE_MISSING；损坏、半文件、错库或不确定 IO 锁写并保留证据。不会自动截断重下、覆盖半文件、读取原输入路径或访问相机。已有任何状态/tombstone 优先过滤，恢复不改用户决策。产物检查改为 1024 字节回读比较，写头/像素也不再申请拼接副本。

仍有全幅灰度（至多 4 MiB）和 g4 缓冲；POSIX 库打开仍可能读整份有界日志，不能宣称所有内存常数化或照搬 MCU。源恢复校验依赖 CRC 而非输入逐字节对比，不构成对恶意篡改的认证。

## 恢复策略

IO 失败、错库、回读不符或不确定写入：停止并锁写本会话，保留全部证据，不删除/截断/覆盖，不确认远端成功。

重新打开库并提供相同 ID/描述符/数据重试：完整且逐字节匹配的产物跳过创建，补齐缺失产物再提交索引。索引已持久化但回调返回失败时，重放发现现有 ID，过滤重入，不增加序号或改决策。不完整、尾随、描述符或内容不符的产物继续拒绝，等待显式隔离/修复；PFJ1 坏尾仍只读恢复，不能跳过追加。

当前支持显式按 photo-id 从本地恢复完整产物，不承诺全部断点无人值守恢复。尚无目录自动扫描、半文件清理或缓存版本更新入口。

## 主机工具

以下仅是实验 ID，不代表相机身份。目录需预先存在且空；工具不格式化、不自动初始化非空库：

```sh
mkdir /tmp/gr4-offline-library
./build-host/host/frame_import create /tmp/gr4-offline-library \
  01000000000000000000000000000000 02000000000000000000000000000000 input.jpg
./build-host/host/frame_import open /tmp/gr4-offline-library \
  01000000000000000000000000000000 02000000000000000000000000000000 input.jpg
./build-host/host/frame_import recover /tmp/gr4-offline-library \
  01000000000000000000000000000000 02000000000000000000000000000000
```

重复 `create` 拒绝；`open`/`recover` 要求现有库绑定匹配。`recover` 不需要原输入或相机。退出码 0 成功/已过滤、1 停止、2 参数错误、3 待渲染、4 缺源。原输入始终只读。输出不要直接当作 Pico 正式 SD 库，设备尚无这条链路的读取/管理入口。

## 验证与边界

- CTest 12/12，C 主机目标 ASan/UBSan；合成 JPEG → 缓存 → 索引真实临时文件与 CLI 集成测试。
- 24 个 IO 回调边界分别注入写前失败、完整写后失败、部分写后失败，共 72 次重开检查。
- 源已保存后的完成接口另覆盖 20 个回调边界 × 3 种故障和重开；源校验失败、索引完整/部分不确定写入都不绕过锁写或防重入。
- 意图/缓存头逐字节变异、意图所有截断点、缓存损坏/奇数填充、错库/坏 JPEG、符号/硬链接、tombstone 防重入。
- 全尺寸 CLI 缓存，验证源图副本 SHA256 一致、输入不变、幂等导入、非空库与错库拒绝后索引/缓存不变。
- 增量 CRC、PFU1 逐字节损坏/所有截断点、不申请灰度的完整 JPEG 校验、每个合成 JPEG 截断点、灰度/缓存分配失败后的源保留、本地恢复、完整暂存补成品、缺源/错库/损坏只读恢复；严格与显式缩放接口对小图逐字节等价。
- 核心通过 ESP-IDF 6.1 编译，但设备入口未调用新事务，未烧写、未验证真机断电。

待实现：非 seek 的流式 HTTP 接收、FatFS 产物适配和单写入任务、持久化错误分类、目录扫描/半文件隔离及空间回收、profile 更新重渲染、Flash 摘要/用户决策镜像、ACK_PENDING 与协议确认。索引提交不等于 ACK 门禁满足，本模块没有网络 IO。
