# 介质接口与 FatFS 映射

实现：`frame_core/frame_media.c`、`frame_fatfs/frame_fatfs.c`、`main/storage_selftest.c`。当前是上板前适配/诊断，不是正式照片库。

`frame_media_io_t` 把固定库文件的 size、范围读、同步替换、同步追加、回收、空目录检查和内存分配与生命周期核心分离。调用方独占目录并在同一任务串行调用；没有隐式锁文件、mkdir、format、NVS erase 或 SD remount。

启动仅将两个有界快照读入分配内存；日志使用 1216 字节块（16 包）扫描，不申请整份 4 MiB 日志。快照和检查点缓冲在设备上分配 PSRAM，数据校验/回读期间有让步。catalog 仍为调用方完整数组，快照重复身份校验为线性两两比较；大库启动性能尚须实机评估。

每次追加前核验 library-id，检查点每个槽替换前也核验绑定。IO 失败拒绝打开；结构损坏尾部可以只读打开有效前缀，不自动修复。两槽回读验证后才回收日志；创建失败保留文件，非空目录不可重建。

FatFS 映射使用 fopen/fdopen、fwrite、fflush、fsync、fclose，回收使用 ftruncate + fsync；本机锁定 ESP-IDF v6.1 源码的 VFS fsync 调用 FatFS f_sync。设备不使用 POSIX directory-fsync/flock/openat；不能因此推断它具有主机适配相同的硬件掉电行为。所有回调前/后检查卡可用性，BSP 拔卡锁存机制需真实设备验证。

适配根目录必须是受信任的专用目录。只允许 library.id、snapshot.0、snapshot.1、journal 四个名字。FatFS 无符号/硬链接；同一实现的主机分支拒绝链接，但不提供原 POSIX 参考适配的 writer-lock/inode 会话保护，不能让两个适配会话同时访问目录。

主机测试复用相同文件映射代码进行真实临时文件往返和卡不可用模拟；内存介质测试枚举检查点及打开流程的每个 IO 回调失败位置，包含部分写入、全写后同步失败和回收后失败。它证明软件决策与恢复顺序，不证明 microSD 控制器缓存行为。

固件默认关闭存储写测试。显式诊断模式在 `/frame/storage-test` 验证创建、KEEP、双快照与重开，使用固定 fixture 身份，不从相机读取数据；未知/损坏/非空库拒绝重建。测试步骤见 [上板验证清单](HARDWARE-GATE.md)。

仅诊断入口 `main/storage_directory.c` 新增目录准备：在已存在、受信任、独占的挂载根下创建固定 `/frame`、`/frame/storage-test`，不创建挂载根、不递归、不删除/格式化；默认照片入口与便携介质核心不改变。创建前后检查介质可用性，EEXIST 后重新验证目录；测试子目录未知名字或非普通文件拒绝，主机分支也拒绝符号/硬链接，已有合法名字的内容交给原核心校验。失败保留空目录及所有文件，不以清空重建掩盖损坏。目录持久化和掉电可靠性仍待真机验证。

新增主机安全测试覆盖重复准备、挂载根缺失、介质不可用/回调边界失效、父路径是文件、未知文件保留、合法名字是目录/链接、父/子目录链接和已有文件不变。全量 CTest 18/18（ASan/UBSan）；不证明 SD 控制器缓存行为。

后续仍需：真实 FatFS API/介质测试、生产库身份生成与换卡交互、单写入服务、源 JPEG/渲染缓存事务、Flash 摘要与补偿。相机 ACK 不得仅凭此适配成功启用。
