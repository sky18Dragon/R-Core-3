## 调用与权限边界

`gr4_confirmation.h` / `io/gr4_confirmation.c` 是SDK适配层，不进入便携选择器。调用方在SDK和输入任务启动前，对整个启动期存活的静态对象调用 `frame_gr4_confirmation_init()`，再通过 `frame_gr4_scan_session_bind_confirmation()` 绑定已prepare、未启动的会话。每个对象仅一次初始化/绑定；禁止清零重用、栈临时对象、释放、重置或删除队列。

初始化创建两条深度1的FreeRTOS静态队列：host向输入任务发送候选提示，输入任务向host提交不可变的决定。提示仅含本次epoch、candidate_id、services与非零64位boot_nonce；不含地址、名称、型号、序列号或认证标志。未来设备入口必须从硬件随机源生成新启动nonce，不使用固定值/持久化值；这只是降低跨启动旧消息匹配风险，不是密码认证、绝对不重复保证或用户同意。

输入任务只调用 `receive()` / `submit()`：不从ISR调用，参数为调用方独立存储，不与通道/会话对象别名，发送期间消息不可修改。初始化对象需经任务创建/同步后再交给输入任务，ready/队列句柄保持不变。返回true只证明提示交付或消息入队，不证明有效确认、连接或身份读取。

host在30秒观察结束、禁收/取消/inactive与新鲜度核对后，发布唯一提示。既有100ms host timer消费回复，每tick最多一条，无无限排空/重试；所有队列收发使用0等待tick，无覆盖已有回复。队列操作仍有SDK内部临界区，不称硬实时或无任何调度延迟。

host逐字段核对nonce/epoch/id/services；错误或旧消息仅丢弃，不消费候选、不延期。匹配的拒绝结束本轮为CANCELLED，匹配的确认才沿已有Owner prepare和一次激活路径走。代码中的true来自核对后的ACCEPT消息，不是默认/自动同意。没有消息不会连接，唯一候选不会自动连接。实际输入驱动仍需保证“新的人工作用”，不能把保持按键、电源操作或旧聊天室授权转换为当次确认。

host先核对5秒确认新鲜度，再消费消息；积压至过期的确认不能延长窗口。Owner交接再次取时钟核对，主任务关闭栅栏和85秒独立全流程期限仍有效。radio activate/等待成功不等于相机身份已认证。

## 关闭与迟到生产者

匹配决定、取消、reset、过期、失败或host退出后的退休均封闭通道；关闭不可再次publish/bind。只有host或host退出后的清理任务可修改封闭状态。输入任务仅访问静态队列和C11原子open门，不访问NPL队列、Owner、SDK生命周期、时钟或板卡对象。

输入发送可能已读到open=true，然后host关闭，再完成入队。这时入队返回true也不放行：host已关闭、不再消费；静态队列始终保留，迟到发送不会触及已销毁的NPL队列或释放内存。receive前后检查open，已知关闭时清零输出；不能将已取得提示视为仍有效或以输入端检查替代host复核。

刻意不删除/重置/排空队列，避免与未完成发送竞态。队列保留不代表未来触摸/串口生产者任务已退出，也不证明I2C/USB/PMU清理；实际驱动必须另有有界退出/静默屏障后才能释放板卡资源。当前不存在该驱动，不能提前将这一项标通过。
