# 多照片日志核心（2026-10-01）

`components/frame_core/frame_catalog.c` 是介质无关的单写入者状态核心，不是已经接入 SD/Flash 的照片库。

## 已实现

- 调用方提供内存，最多 5000 个身份；包括删除记录，不自动淘汰 tombstone。
- 新身份从 sequence 0 / NEW 开始；更新必须带当前 sequence，避免过期后台回调覆盖用户决策。
- 更新先编码现有 40 字节 PFR1 记录，调用持久化回调；只有回调成功才发布内存状态。
- 回调失败可能已写出部分或完整记录，因此立即锁定写入，不能直接重试。重新打开并恢复日志后才能判断实际状态。
- 支持交错多照片记录和逐条流式恢复；CRC、状态迁移、序列连续性或容量校验失败时保留有效前缀并停止，不跳过坏记录。
- 不完整尾部锁定写入。修复必须由未来介质层验证库身份、保存证据、处理尾部后重新恢复，不提供自动截断接口。

## 适配契约

`frame_commit_fn` 返回 true 必须表示记录已达到适配层声明的持久化条件，不能仅表示 fwrite 成功。回调不得重入或修改 catalog；所有查找、恢复、写入由同一任务串行化。`find` 返回内部只读指针，不能跨并发操作持有。

身份由上层提供，核心不从相机路径生成身份，也不证明强身份成立。PFR1 没有 library-id、全局事务序号和文件校验摘要；新增的 `frame_storage` 包装层提供库绑定与全局提交序号，详见 [存储格式](STORAGE-FORMAT.md)。正式适配应使用包装层，不能直接将裸 PFR1 写入库。目前仍不得据此允许远端 ACK。

当前采用线性查找、调用方驻留完整 frame_photo_t 数组，5000 条占 `5000 * sizeof(frame_photo_t)` 字节；ESP32 上应由适配层分配 PSRAM。这不是架构方案中的最终紧凑索引，启动耗时与功耗尚未测量。

## 待实现

SD/Flash IO 适配、库身份绑定文件、双槽落盘、源图/缓存事务、跨介质补偿、写入任务集成、Flash 分区，以及拔卡/满卡/真实断电验证均未完成。库绑定日志编码和双快照校验/选择已实现并经主机测试；不是已落盘的生产库。当前固件 Demo 0 仍只显示测试图，未调用 catalog。

## 测试

主机 ASan/UBSan 测试覆盖多照片交错恢复、全部尾截断点、每字节 CRC 破坏、失败提交的 0–40 字节写入、序列重复/跳号/非法迁移、容量不足及真实 5000 条上限；模拟日志回调不是物理 SD 掉电模型。
