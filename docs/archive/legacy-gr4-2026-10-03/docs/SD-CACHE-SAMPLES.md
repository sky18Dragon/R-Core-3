## 流程与保护范围

显式 `FRAME_SD_CACHE_SAMPLES=ON`，与启动探针、存储诊断和旧嵌入显示互斥。私有 `FRAME_DISPLAY_SAMPLE_DIR` 必须提供三份 `sample_N.pfg`，每份 415952 字节：80 字节 PFG1 加 415872 字节 1216×684 g4。不修改驱动、波形、时序及 PMU 校准；不格式化、不擦 NVS、没有相机 IO。

1. 所有嵌入包先校验固定库／照片 ID、Cover layout=2、尺寸和完整 CRC，错误不创建目录。
2. 仅在已挂载卡上准备 `/frame/cache-test`，保留 `/frame/storage-test`。未知条目、非法文件类型、错库／损坏状态拒绝，不删除或自动修复。
3. 缺失的固定缓存独占创建，1024 字节分块写入，flush/fsync/close 后全文件逐块比较，每块检查介质和库绑定。已有缓存仅比较，不符保留并停止、不覆盖。
4. 缓存验证后才导入 NEW 并 KEEP；checkpoint 后关闭／重开，要求三个 KEPT（各 revision=1）及 global sequence=6。已有完整夹具不重复提交或写 checkpoint。
5. 每次显示从 SD 经 `frame_fatfs_cache_load` 读入独立 PSRAM 暂存区，绑定／头／长度／完整 payload CRC 检查成功才拷贝驱动 framebuffer 并 GC16。可信 expected 来自预先验证的嵌入包，不从卡上任意缓存回填。
6. 顺序 1→2→3，前两张各保持 30 秒，第三张保持。读失败不刷新、不用嵌入像素兜底，保留此前面板画面。

准备函数可主机测试、不依赖 ESP-IDF。实际 FatFS fsync／目录元数据及突然掉电尚需设备验证，不能由 POSIX 测试推断电气掉电可靠性。残缺缓存不自动修复，重试可能安全停止，须人工决定清理独立测试目录后继续。

## 素材与边界

使用用户三张私人原图，原图 SHA256 不变。主机 `sips` 生成去白框／重新编码的私有 JPEG 副本，再由 `frame_cache_fixture` 按完整副本 Cover 渲染合法 PFG1，记录真实副本大小／CRC；不把旧 ROI 原始 g4 冒充正式 Cover 缓存。三份 payload 与独立 `frame_convert --cover` 输出逐字节比较，头／源／payload CRC 校验。

副本不是旧素材的逐字节复用，JPEG 重新编码可能产生细微灰阶差异。副本、预览、包、构建和设备备份保留在忽略的本地私有目录，不提交或上传。诊断只在 SD 保存缓存和测试索引，**没有把源 JPEG 落盘到 SD**；不证明设备 JPEG 解码／正式导入源文件耐久性，不启用相机远端 ACK，不可用于产品“源照片已安全保存”的判定。

### 只读差异检查模式

`FRAME_SD_CACHE_SAMPLES=ON` 与 `FRAME_SD_CACHE_INSPECT_ONLY=ON` 显式组合生成 `sd-cache-inspect` 专用产物。应用检查现有固定目录／库绑定，只读打开三个固定 cache-test 文件；不调用准备、导入、KEEP、checkpoint 或照片刷新，缺目录／文件停止该项、不创建或修复。BSP 初始化及挂载仍运行，故不是整机硬件写保护或独立掉电测量；不格式化、不擦 NVS、不写 PMU 校准。

`SD_CACHE_INSPECT` 每项报告：完成与否、阶段／errno、文件大小、首个不一致字节（包含 80 字节头的文件偏移）、头是否有效／哪些字段不同、完整 payload 标记及预期／实际 CRC。完整相同文件 first_diff=4294967295；截断但已有部分相同则 first_diff=文件大小。`ok=1` 只表示检查过程完成，**不表示缓存正确**；必须结合 first_diff／header_mask／payload_complete／CRC。长度在 80 至 415952 之外拒绝；截断或 IO 中断的 CRC 不代表完整 payload。

header_mask 的位 0–13 依次对应 magic、schema、库 ID、照片 ID、源大小、源 CRC、宽、高、profile、layout、缓存 CRC、payload 长度、保留字段、头 CRC。只报告字段分组和校验值，不输出实际 ID、文件路径、像素字节；头损坏时仍按可信固定尺寸检查实际剩余 payload，不按损坏头分配或访问。所有证据留本地私有采集日志。

主机覆盖完整三图、像素单字节变化（first_diff=80）、损坏 magic、合法但不同 Fit 头（first_diff=60、layout／头 CRC 两位）、介质失效、缺目录／缺文件不创建，错误内容不修复。专用产物门禁要求只读模式标志／检查函数和三个合法嵌入范围，拒绝准备／索引提交入口；不能用此静态门禁替代真实 SD 行为验收。

分阶段诊断 API `frame_cache_samples_prepare_report` 保留原准备流程和停止／保留策略，旧 bool 接口作为包装保留。失败输出 `SD_CACHE_STAGE_FAIL stage=… index=… offset=… errno=… created_library=…`；固定阶段名涵盖输入校验／目录／开库建库／缓存创建、分块写、flush、fsync、关闭、长度、分块比较／导入、KEEP、checkpoint、重开。index=0 表示非某张图，offset 是当前块起始或操作边界，不是坏像素位置；errno=0 可能是逻辑校验或介质检查失败，非零也仅作系统错误线索，不等于根因。首次失败信息在关闭清理前保存，避免被 fclose 覆盖；不输出文件名／私人路径／内容。

成功时 `SD_CACHE_LIBRARY source=created|existing` 表示本次是否成功新建库，不证明所有缓存文件已有或严格无 SD 写入；此前部分库仍可能补提交。跨重启验收不能只凭 existing 标记，需结合状态／缓存及实际执行路径。诊断输出不修复文件、不绕过校验，不改驱动／波形／校准。
