## 布局隔离

PFI1／PFU1／PFG1 仍为 schema=1、80 字节、小端及头 CRC；偏移 60 的 layout 扩展为：

| layout | 行为 |
| --- | --- |
| 1 / FRAME_LAYOUT_FIT | 旧完整构图 Fit，保留旧源凭据／缓存兼容 |
| 2 / FRAME_LAYOUT_COVER_CENTER | 全源图按 EXIF 纠正后等比居中裁切、铺满输出、不拉伸 |
| 其他 | 拒绝，不猜测或自动降级 |

profile 仍仅 1；源大小／缓存尺寸上限不变。layout=2 不包含显式 ROI、自动去白框或可调裁切位置；三图嵌入诊断中的私人白框 ROI 不可冒充本布局的正式缓存。以后增加裁切位置必须扩展可持久化的描述符与标识。

`frame_files_ingest_layout` 显式选择布局；旧 `frame_files_ingest` 与 CLI 无参数仍 Fit 兼容，`frame_import create|open ... source.jpg --cover` 生成 Cover 凭据／缓存。`recover` 根据持久化 PFU1 的 layout 重渲染，不需要原输入／相机。源已保存后分配失败，Fit／Cover 都保持 RENDER_PENDING、无 NEW 提交；本地恢复后缓存与对应渲染参考逐字节一致。

同 ID 已登记的任何状态仍优先过滤，不迁移／覆盖旧 Fit 缓存或用户决策。未登记但已有不同布局凭据时，停止并锁写会话、保留文件；重新打开后可按原凭据恢复。现阶段没有把已提交 Fit 图自动升级到 Cover 的入口，不能把“拒绝误用”宣传成已完成缓存版本迁移。

## 显示前读回门禁

可移植 `frame_cache_load` 不依赖 ESP-IDF，仅有 size／按偏移 read／yield 回调，无写接口。调用者提供可信 expected 描述符，不能从待读缓存自身解码后回填 expected 来绕过布局／身份校验。

1. 先编码并验证 expected：库／照片 ID、源大小／CRC、几何、profile／layout、缓存 CRC。
2. 精确核对文件总长和完整头；尾随数据／旧布局／错身份拒绝。
3. 使用不超过 1024 字节的单次读取填入调用者的独立 g4 暂存区，增量 CRC，每块让步。
4. 读后再核对总长／头／库绑定，确认 payload CRC、奇数宽度末尾白 nibble。
5. 只有成功后，显示适配层才可把暂存区发布到驱动 framebuffer 并刷新。失败可能留下部分暂存字节，绝不能显示；保留此前面板画面。

长度／头复核不能防御恶意并发改写或 CRC 碰撞；CRC 非认证。需要可信根目录与单写入会话，调用者负责 UI 状态／介质生命周期和更新同步。本实现仍需要整份 g4 暂存内存，不是零整帧分配。

## FatFS／主机文件适配

`frame_fatfs_cache_load` 借用已初始化适配器和恢复完成的 storage，要求库 ID 相符、索引存在同 photo-id、状态 NEW／NORMAL／KEPT、无 delete_pending，拒绝 PUT_AWAY／未提交／只读异常库。路径只由 16 字节 ID 转成固定 32 位 hex 文件名 `<id>.g4`，不接受相机原始路径。

只读打开文件，先检查已打开对象是普通文件；POSIX 测试后端额外拒绝符号／硬链接和 FIFO 阻塞，FatFS 本身没有这些链接对象。每次 size／read 前后复核介质存在及 PFB1 library.id 绑定，读取结束／关闭成功后再次复核。实现不创建／删除／覆盖／修复文件、不挂载／格式化／擦 NVS／写 VCOM；不构成整个 BSP 的硬件写保护。

当前每个读块多次回读绑定文件，需实机测量读耗时／功耗后再优化，不能照主机速度推断 SD 性能。接口已接入独立 SD 缓存显示诊断，尚未接正常产品产物写入、正式介质代次或单写入任务。
