## 最新软件：配网与manager共享无线控制、检查式停机

manager普通连接/断开/停机/配置IP不抢占AP；稳定ACTIVE允许候选、扫描、省电和hostname，这些操作也先取连接mutex。STARTING/STOPPING/FAILED拒绝上述操作。候选/扫描API为既有直接调用保留IDLE兼容，扫描仍检查真实AP模式；不是声称所有未知调用者都必须取得服务lease。只读getter不授予控制权，原生AP已改用begin，不以裸接口判断能否停止无线。

AP停止先取消保存ticket，再quiesce：policy锁内取消目标/自动重连并给等待者失败位，然后非阻塞取得连接mutex。候选或扫描仍占用时返回错误、保留DNS/HTTP/radio，不执行SDK退出；FAILED finish可以记录故障，但绝不释放候选的mutex。候选完成自身清理并释放后，后续显式stop才能取得控制并按原顺序退出；不自动循环/强删。候选在准备后、arm前再次核对阶段；取消扫描在列表清理/模式恢复后不复制旧结果。app事件回调继续用policy锁而非连接mutex，检查目标/阶段，避免回调阻塞连接等待并避免取消之后重新启动旧目标；未保证已开始SDK调用瞬间终止。

## 此前软件：配网DNS报文边界与端口关闭确认

Read Pico新增便携`captive_dns`：输入最大512字节，先检查完整头部、单个IN问题、非压缩标签/名称及可选单个EDNS OPT；响应单独构造且检查调用方容量，失败不改输出。A问题返回固定AP IPv4，其他IN类型返回零答案，不伪造IPv6或递归/认证标记。校验OPT完整长度/选项边界，未知选项不回显；响应OPT声明512字节，保留DO，未知版本返回BADVERS。相关布局/限制参考[RFC1035](https://www.rfc-editor.org/rfc/rfc1035)与[EDNS0 RFC6891](https://www.rfc-editor.org/rfc/rfc6891.html)。这是受限配网UDP协议，不是通用DNS解析器、DNSSEC或完整RFC兼容实现；压缩问题、多问题、非IN、畸形报文直接忽略，不宣称实现标准的全部错误响应/TCP/缓存语义。

## 文件格式与读取边界

Read Pico依次检查`/storage/config/wifi.txt`、`/storage/wifi.txt`；只有首路径不存在才退到根文件，IO/权限/无效父路径或坏的首文件不以根文件掩盖。`storage_read_wifi_config`要求有效持久SD介质、非空普通文件≤1024字节、完整长度/EOF/读取错误/关闭和最终介质检查；失败输出不变，关闭不确定锁存SD。原文件不删除、改名或重写。

格式沿用位置行：网络名、密码、可选设备名，支持LF/CRLF和无末尾换行，跳过空行及首字符`#`的注释，不裁掉字段首尾空格。拒绝NUL/控制字节（包括注释内）、孤立CR、额外字段和超限，不截取前缀。SSID≤32字节（非字符数），密码为空或8–63个ASCII可打印字符，64位仅允许十六进制PSK；设备名≤63字节。WEP/企业认证等不在此契约。

空行保留旧分隔符语义，不暗中当作开放网络密码。开放网络用第二字段`""`显式表示；其他位置的引号不解码。首字符`#`的SSID/密码无法在此旧位置格式表示，可以通过配网页面输入，不能宣称此文本格式支持全部任意二进制SSID。Read Pico C字符串容量改为33/65以容纳完整32/64字节wire字段；原板保持32/64容量和原行为。

读文件现在只返回结构，不在验证/关闭前保存设备名。真实main仅在读取通过后保存凭据及可选名称；读取失败（非NOT_FOUND）或保存失败停止此分支，不自动当成无配置启动AP、重启或报成功。缺失文件仍保留上游OOBE流程。名称新增检查式保存，set/commit完成才改变RAM值；但凭据两键、设备名及其他参数**不是一个原子事务**，失败可能已留下部分NVS结果，不伪称回滚。运行时各错误退出的完整资源收敛仍待审查，不能把源码return当作整机退出验收。

## 连接失败时保留NVS，使用本次配网完成门禁

新板的`recover_wifi_connection`不删除wifi_ssid/wifi_pass或提交擦除。它停止当前重连、检查正常HTTP停止，进入原配网页面并等待本次新的完整保存后再重启；恢复启动失败返回，不立即擦除/重启或在late任务中反复启动服务器。正常OOBE也等待本次配网完成，不拿“旧NVS已有SSID”或中间写入成功当作本次完成。

`provisioning_session`是易失性原子ticket/完成位，用于现有AP分支的跨任务通知，不是另一套产品配置/相册状态系统。AP begin使旧ticket失效；仅本次凭据/名称保存及响应发送成功才commit。保存失败、过期ticket、重复完成不宣称当前成功；已完成后不再给新保存ticket。不替代NVS事务、响应客户端确认或对已开始写入的回滚。

新板AP启动的模式/配置/启动/IP/DHCP/HTTP/路由/DNS错误传播并尝试清理，不用ESP_ERROR_CHECK制造这一分支的panic重启。HTTP停止失败保留server所有权。候选连接、当前状态和AP保存顺序已有上述软件检查；后台轮播/刷新/休眠与配网同时进行的生命周期、部分初始化/停止和更多SDK调用仍须审查。
