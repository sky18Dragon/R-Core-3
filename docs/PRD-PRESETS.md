# 处理预设：调参保存为预设，上传时按预设渲染

状态：方案已确认（2026-11-05，决策见第 7 节）；一、二期已实现并烧写（`0e46de61…`，见 [验证记录](VALIDATION.md)），用户真机试用确认通过。属于 R2，不改变 [TODO](../TODO.md) 的 R1 范围。现状来自 2026-11-05 对源码的只读核对。

## 1. 需求

| # | 用户原话（概括） | 要解决的问题 |
| --- | --- | --- |
| P1 | 把调参改成预设，可新增、删除，调试出的参数存成预设 | 调出的好参数只能“设为默认”，存不下多套，换设备就丢 |
| P2 | 上传照片时可以选择预设渲染 | 人像、风景、夜景适合不同参数，现在只能整体改默认 |

## 2. 现状

- 相框只存一套“默认处理参数”（NVS `proc_*` 13 个键），网页上传与相框自行处理 JPG（`image_processor.c`）都用它。
- 网页里有 5 个写死的内置预设（均衡/动感/鲜艳/柔和/黑白），不能改删。
- 调参页的候选与轮次只存在浏览器 localStorage。
- 相框存的是处理后的 16 灰成品，不存原图（[照片方向 D2](PRD-PHOTO-ORIENTATION.md)）：预设只在上传时生效，已上传照片换预设需重传。

## 3. 概念

- **预设** = 有名字的一套画质参数：曝光、饱和度、色调映射（对比度或 S 曲线四项）、颜色匹配、抖动算法、压缩动态范围。**不含摆放**（铺满/留边、背景色），摆放按每张照片在上传框里定。
- **只有“我的预设”**：网页不再出现内置的 5 个预设（决策 D3）。最多 20 个，可新建、改名、改参数、复制、删除。
- **默认预设**（★）：全局一个。上传时默认选它；设为默认时把参数写进相框现有的默认处理参数，相框自行处理的图片随之生效。

## 4. 设计

### 4.1 「预设」页（原「调参」）

- 列表：每个预设一张卡片——名称、★、与默认相比的差异摘要、来源（调参/手动/复制/迁移）。菜单：设为默认、调试、编辑、复制、改名、删除。默认预设须先另选默认才能删；只剩一个时不能删。
- 「新建预设」：**调参挑选**（逐轮淘汰流程）、**复制已有**、**手动调**（从默认开始拖滑块）。
- 调参流程沿用现有页面（测试照片、摆放、整屏带字母轮播、淘汰、2×2 同屏比较），开始前选**基准预设**，候选围绕它展开（基准本身 + 其他预设 + 曝光/对比度/S 曲线/颜色匹配/抖动/动态范围的变化）。最后一步「保存为预设」：填名称，可勾“同时设为默认”；从某个预设点“调试”进来时另有“更新该预设”。
- 编辑单个预设：处理参数滑块 + “在相框上看看”（用测试照片整屏显示，角标为预设名首字）。

### 4.2 上传时选预设

- 上传框「图像处理」顶部是预设选择，默认选中 ★；整批照片使用它。
- 单张可改：照片编辑里“这张用：××”；队列缩略图角标显示非整批预设的名字。
- 微调滑块仍在：拖动后名称显示“××（已调整）”，并可“存为新预设”；不影响原预设。
- 摆放（铺满/留边、背景色）单独一行，改动即保存为默认摆放。

### 4.3 照片记录所用预设

- 上传后写入相册索引 `.photos.json`：`{"up": 90, "added": …, "preset": "人像"}`（存名字，预设改名或删除后照片仍显示当时的名字）。
- `/api/images` 返回 `preset`；看大图时显示“渲染：人像”。

## 5. 数据与接口

- 存储：存储根目录 `/.presets.json`，写 `.new` → 换名，断电回退 `.old`（与照片索引同一做法）。

  ```json
  {"version": 1, "rev": 7, "default": "p2",
   "presets": [{"id": "p2", "name": "人像", "source": "tuning",
                "params": {"exposure": 1.0, "contrast": 1.1, "...": "..."},
                "created": 1793800000, "updated": 1793800000}]}
  ```

- `GET /api/presets`：没有文件时返回空列表（`rev` 0）；无存储返回 404。
- `PUT /api/presets`：整份写入，`rev` 须等于相框当前值，否则 409 并返回最新内容（两台设备同时改时提示刷新）；成功后 `rev` + 1。服务端校验：最多 20 个、id 唯一、名称 1–64 字节、参数取值合法、`default` 指向存在的预设或为 null。
- `PATCH /api/photo` 增加可选 `preset`（名称，≤ 64 字节）；`up` 与 `preset` 至少给一个。
- 默认参数仍以 NVS 为准：设为默认 = 写 `presets.default` + `POST /api/settings/processing`（保留当前摆放）。二者不一致时（例如旧入口改过默认），列表标“默认（已修改）”。
- 迁移：首次打开且相框没有预设时，把当前默认参数存成预设“我的默认”并设为 ★。

## 6. 边界

- 无存储卡：预设无法保存，页面提示；上传仍用默认参数。
- 删除被照片用过的预设：照片不受影响（已渲染），信息里仍显示当时的名字。
- 黑白屏：饱和度不显示、不参与差异摘要。
- 调参进行中的轮次仍只存本浏览器；保存下来的预设才进相框。

## 7. 决策（2026-11-05 用户确认）

| 编号 | 问题 | 决定 |
| --- | --- | --- |
| D1 | 预设存在哪 | 相框存储卡 `/.presets.json` |
| D2 | 预设是否包含摆放 | 不包含，摆放按每张照片定 |
| D3 | 内置 5 个预设 | **删除**（用户改定；推荐原为保留只读） |
| D4 | 上传选预设粒度 | 整批选，单张可改 |
| D5 | 已上传照片换预设 | 暂不支持，需重传 |
| D6 | 相册默认预设 | 放到三期 |

## 8. 分期

| 期 | 内容 |
| --- | --- |
| 一 | 预设文件与接口、迁移；「预设」页（列表、新建、复制、改名、删除、设默认、编辑）；调参结果保存为预设；网页去掉内置预设 |
| 二 | 上传选预设（整批 + 单张）；照片记录所用预设；大图显示 |
