# 测试策略（分层、按改动触发）

本文件是测试做什么、何时做的唯一规则；各层结果只写进 [VALIDATION](VALIDATION.md)。目标：日常迭代秒级反馈，重步骤只在候选固件上做一次，不为每个小改动重复。

## 四层测试

| 层 | 何时跑 | 内容 | 耗时 | 入口 |
| --- | --- | --- | --- | --- |
| T0 快速 | 每次改完代码 | 主机增量编译 + 全部CTest（并行）+ Python构建/控制台防护 | 约15秒（2026-10-19实测：1301项CTest、96项Python） | `scripts/test_quick.sh` |
| T1 提交前 | 提交/合并前一次 | T0 + ASan/UBSan全量主机测试 + R1 local-frame固件编译 | ASan约1分钟（2026-10-19实测含重建56秒）；固件编译数分钟（估计） | `scripts/test_quick.sh --asan --firmware` |
| T2 候选 | 每个要上板的候选一次 | T1 + 原板及全部Read Pico profile编译 + Web测试/生产构建 | 数十分钟（估计） | `scripts/test_quick.sh --asan --firmware --all-profiles` 与 `npm --prefix webapp test` |
| T3 真机 | 每个R1候选一次 | 下节“R1真机验收单”，一次会话完成 | 约30–60分钟含人工（估计） | 人工 |

规则：
- **文档/注释改动**：不跑任何测试，只做链接检查（见下）。
- **专注调试**：`scripts/test_quick.sh -R <正则>` 只跑相关CTest。
- **ASan只在T1及以上跑**，不在每轮改动后重复；出现内存类缺陷、改动分配/缓冲/解析代码时提前跑。
- **固件编译按触及范围选**：只改 `main/`、HTTP/上传/配置/相册等PhotoFrame业务 → 只编R1 local-frame；改了 `components/board_hal`、`epaper_driver_read_pico`、`read_pico_display`、`boards/` 或 `build.py` → 加编对应诊断profile；改了公共HAL/显示契约 → 加编原板。**不再为每次改动六配置全编。**
- **新增可主机测试的逻辑**（算法、格式、协议、状态）必须带主机测试；ESP-IDF/板级IO靠编译+T3，不为纯IO胶水造替身测试堆。
- **不做的事**：不按测试数量或勾选数计算完成度；不为尚未启用的R2功能（URL多跳、远程配置、OTA、PMU睡眠）新增专项测试，除非该代码路径在R1里仍可达（可达则应禁用而不是加测）。

## 改动类型 → 最小测试

| 改动 | 最小集 |
| --- | --- |
| 文档 | 链接检查 |
| 图像/JPEG/PNG、路径、配置、上传、HTTP逻辑 | T0；提交前T1 |
| `main/` 里调用SDK的胶水、`build.py`、Kconfig/defaults | T0 + local-frame编译 |
| 板级HAL、显示后端、SD驱动 | T0 + 对应profile编译；真机只在候选T3里验 |
| Web前端 `webapp/` | `npm --prefix webapp test`；发布前生产构建 |
| 准备烧写 | T2 全部，再T3 |

## T3：R1真机验收单（取代逐步骤单次授权的诊断流程）

候选固件通过T2后，一次授权覆盖：确认设备/分区 → app-only写入 → 全长回读 → 下列清单，不拆成多轮独立授权。授权范围由用户在聊天里一次确认；不自动格式化SD、擦除NVS、写VCOM/校准或改波形。

| # | 动作 | 通过标准 |
| --- | --- | --- |
| 1 | 启动、串口日志无panic、屏上显示开机页 | 启动到服务就绪 |
| 2 | 手机/电脑连AP或同网，打开管理页 | 页面可访问 |
| 3 | 上传3张不同图 | 各自成功、SD出现原片、相册可见 |
| 4 | 逐张选图显示 | 方向正确、Cover居中、不拉伸、无异常条带 |
| 5 | 设3张轮播、短间隔，跑2轮后停止 | 顺序正确，停止后不再换图 |
| 6 | 断电重启 | 文件与配置保留，能再显示/轮播 |
| 7 | 失败路径各一次：无卡、坏图、超限 | 明确报错，不崩溃，原片未损 |
| 8 | 一张16阶标准页 | 沿用已验证的GC16路径，无回归 |

每项只记录“通过/失败/现象”和日志位置。失败即停并修，不为一项失败重做已通过项（除非修复触及其路径）。以前的逐张白参考、`clear-white`/`white-confirm`/`pattern-confirm` 分步流程仅保留给显示后端自身改动，R1回归不使用。

## 固定约束（不因精简而放松）

- VCOM只读；不自动格式化SD；不自动擦除NVS；相机原片不可删除。
- 烧写/回读前仍需用户在聊天明确确认本次镜像与范围；旧授权不延续。
- 主机测试、编译、烧写回读、真机结果分开记录；不把编译通过写成功能验收。
