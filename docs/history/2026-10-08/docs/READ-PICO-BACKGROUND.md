## 创建与发布

`read_pico_background` 是四个固定角色的 SDK 适配，不是新的相册/产品状态系统。每个启动只有一份永久槽位，逐次检查 `xTaskCreate == pdPASS`，保留原任务名称、优先级和栈字节数。固定 ESP-IDF 的栈大小单位为字节，不按 vanilla FreeRTOS 的 word 数理解。

创建后的包装任务先等待，不能立即调用原业务函数。电源初始化创建需要的 sleep 和 rotation；main 创建 button，连接超时时再创建 late Wi-Fi。全部必需角色已创建才调用检查式 HTTP ready 发布，然后原子放行任务。创建/发布错误不打印该分支启动成功；既有任务收到取消，自行退出，不跨任务强删。重复创建、重复发布和取消后的重建均拒绝，槽位在本次启动不复用。

Read Pico main 包装原启动函数；启动返回且门禁未活动时请求取消等待任务，最多2秒确认回调返回后才尝试关闭仍ready的本角色HTTP；退出未确认则不继续HTTP清理。电源、其后的 OTA/相册及配网初始化错误改检查式返回，避免这些分支以 panic 重启代替任务错误报告。此前其他初始化、周期 timer、mDNS、显示/SD 和 SDK 内部对象并不因此自动销毁。HTTP startup 失败还检查本角色 stop；底层 HTTP stop 仍可能无界等待，不把它当有界整机清理。

PMU睡眠门禁不变。四处条件提前睡眠在Read Pico上返回时不再继续轮播；CLEAR和timer/rotate唤醒流程返回时不再落入普通冷启动。可能已进行的唤醒工作不回滚，wake配置窗口原有HTTP发布行为不是完整后台启动；窗口/失败返回后只按上述检查式退出，不宣称实机睡醒通过。

## 合作取消

原业务函数由包装任务调用，Read Pico 分支须释放本函数资源后 **return**，只有包装任务调用 `vTaskDelete(NULL)`。定时和按键在下一次安全循环边界检查任务门禁及 HTTP ready；late Wi-Fi 不再永久等待 event bit，改 100ms 有界等待并检查事件组、取消和当前连接。在线启动在入口及延迟 OTA 前再次检查门禁。旧板保留原创建、自删除及等待行为。

联网恢复先取消这四类任务，再最多等待 2 秒确认其他回调已返回；只豁免确实正在执行包装回调的当前自有任务。创建/发布控制忙、退出超时都不继续改变无线或关闭 HTTP。正常确认后才沿用原恢复流程；单纯调用 cancel 不宣称退出已确认，超时不强删、不自动复用，可再显式核对。

等待 API 只允许有限预算（至多 5 秒），检查 tick 回绕；确认不等于 FreeRTOS idle 已回收 TCB/栈，也不等于周期 timer、SNTP、HTTP 请求、SDK 默认事件任务或完整资源已退出。取消不是中断已开始的图像处理、HA、文件/NVS/SDK 操作，不能回滚它们。发布与取消竞争时不重新激活，外部 HTTP ready 仍由 main 负责撤销。

## 验证边界

18 项真实适配 C + 合成 FreeRTOS 调度/时间测试：非法参数、角色/重复、等待发布、取消、第一/后续创建失败、就绪失败、重入、创建/发布中取消、有限等待、当前任务豁免与其他任务、已完成句柄复用和 tick 回绕。每项独立进程，无故障状态重置后“复用通过”。

三项 Python 源码断言核对 main/power 接入、创建/就绪/日志顺序、恢复/启动返回先等待再清理、回调返回包装层、睡眠拒绝不继续推进及旧板分支；没有在主机执行巨大 main/power 业务，也不是真实 FreeRTOS 并发/RF/HTTP 验收。全量普通和 ASan/UBSan 各 831 个唯一用例通过，Python 47+17=64；固件最终状态和产物身份以 [VALIDATION](../../../VALIDATION.md) 末节为准。
