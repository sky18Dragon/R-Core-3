# Read Pico 显示：4bpp、GC16 与安全边界

此前已验收`6f2a4ea…` PM锁候选仅factory部署，305,104字节全长回读一致且分区表前后不变。它沿用精确684行、18MHz、factory VCOM、默认36相和80MHz存储，只在显示事务持有CPU/APB max锁。静态清白78/78帧并获人工确认；官方局部页36/36相合计399.327ms，照片16阶中心亮度严格单调，已确认并完整STOPPED。持续白偏根因已关闭，P2其余重复性、图案、照片链路和长期稳定仍未完成。当前设备为原片只读隔离诊断d760371b…/325,904字节，app-only回读/分区保持及S1完整读取/ROM分块解码通过，正常卸载/HAL退出、STOPPED/串口关闭，不启屏。没有活动白参考，旧屏幕画面和解码结果不代表照片显示能力。

C阶段入口`gc16-gray16-labeled-continuous`的历史实测已排除“只缺连续HV”假设：一次锁、上电/主动温度采样和关电内顺序显示GC16白与同一编号图，72/72相仍白偏。固定上游同步绘制仍使用`portMAX_DELAY`，历次正常返回未触发挂起；该限制仍保留。

## 本轮局部图案的布局复核

官方逻辑竖屏坐标u×v为684×1216，原生framebuffer映射为(x,y)=(v,683-u)。灰条应从u=40开始、16条各37像素，结束于u=631；棋盘同样从u=40开始、16×4格各40像素；黑块与20条细线也都保留40像素左边距。实际厂家绘图和独立便携参考全帧逐字节相等，新增边缘断言后普通与ASan/UBSan串行全量回归各297/297通过。

实拍中正常棋盘格节距约46–48照片像素，而左侧同色连续区约132–140照片像素；结合右侧空框定标，表现为约前80逻辑像素异常，连续块延伸到u≈120后才恢复40像素节距。灰条、棋盘、黑块和细线的左边界表现一致，右侧空框、后续格距和垂直布局基本正确。因此源图并不包含该宽区，且不像整幅缩放/旋转；当前优先怀疑framebuffer之后的行映射或物理扫描边界。照片受透视/曝光影响，80像素仅为定位量级，不能当成已测得的硬件常数。

边缘探针轮的新照片在不同手持构图下再次呈现同一几何：物理左边缘至约u=120的连续区仍在，而u≈120后的棋盘节距、右侧空框和垂直分区基本正常。与此同时，u=0/39、40/76、77/79、80/113、114/119、120/127对应的12条source脉冲轨迹具备正确的组内相等和组间差异。因而当前可以排除测试图预期布局以及source回调前的这些关键边界复制，但不能越过证据声称具体是DMA、PCLK、CKV/STV或面板gate故障。

高层全刷把684行与全部608列标为dirty；旧路径为LCD队列补4条hold行到688。精确684行候选不再物理扫描这些填充行，并在同图A/B中恢复几何。相位记录仍不检查每行物理落点，因此不把单次成功扩大为完整电气证明；后续保持gamma、VCOM、频率和波形不变。

### 边缘供数探针

新候选仅在`gc16-gray16-page`启用组合观察，不改变其他GC16图案。每个36相frame仍记录注册、启动和完成时间；line wrapper按source调用序号抽取原生y=683/644、643/607、606/604、603/570、569/564、563/556，共六对12条行。它们对应逻辑u=0/39、40/76、77/79、80/113、114/119、120/127；每对在官方页面上内容相同，而五个组间正好跨越白边、灰码或棋盘相位边界。

回调只对命中的304字节脉冲行计算32位指纹，不分配、不打印、不做IO；36相结束后在任务上下文聚合轨迹。精确684行候选仍观测到每帧696次source调用：684条活动行加两个6行buffer的尾部补取；该数字不是物理扫描行数。12行必须齐全、同组两行每相相等、五个边界至少在一相不同，且无晚到/孤立/溢出；CPU1只允许每帧row0–11作为同步启动预填，后续跨核仍失败。它验证renderer给LCD source回调的数据关系和调用顺序，不验证DMA电气完成或物理gate行号；最终仍以实拍几何为准。

## 灰码、可见级数与白偏根因

`read_pico_pattern_render` 的 gray16 是 16 条各 76 像素的标准码 0–15；实际转换使用 ROTATE_0/不反色，只交换 nibble，没有 gamma、阈值或亮度压缩。后端选择 `E0470_WAVEFORM`、`MODE_GC16` 全刷及 1K LUT；默认生成 36 相，没有选择 GRAY8、DU 或完整 48 相表。

固定厂家[波形头文件](https://github.com/MindReset/read_pico_firmware/blob/28cde682a4468a581c278761922724f57d976418/components/e0470_epaper_waveform/include/e0470_epaper_waveform.h) 对完整 GC16/GL16 表声明约 11 级可分辨；默认裁剪保留灰阶尾段。该声明不是本机实测级数，也不能单凭它解释照片中大段偏白。保持原 16 灰阶目标，实际可见级数和质量未验收，不降低标准或改波形掩盖。

本轮只在主机编译未改的波形生成/裁剪源码，检查白参考 15 → 0–15：默认 36 相与完整 48 相分别都有 16 个不同的时间有序软件序列。部分码的 dark/white/hold 数量相同，序列仍不同；软件序列数不是光学灰阶数。审计用空 IO 头文件桩隔离纯算法，没有验证 ESP 汇编 LUT 输出、DMA、电气脉冲或面板反射率；完整表只作离线对照，未启用到设备。

历史 gate 日志 `live_SY_temperature=0°C` 来自 SY 寄存器 8，但旧路径在 ON=0 待机状态读取，不能当成环境温度。已核对 [Silergy SY7636A Rev.0.9B 手册](https://uploadcdn.oneyac.com/attachments/files/brand_pdf/silergy/81/0E/SILERGY-SY7636ARMC.pdf) 第 4/12/21 页：EN 低清报告寄存器、温度默认值为 0、ON=1 才连续转换。现路径在标准上电/PGOOD/原5ms稳定后主动读取，检查ON/PG/故障/实际PGOOD与0–50°C范围；错误不绘制、关电并锁存。历史28/31/32°C样本仍白偏，而PM锁候选在27°C通过；这些温度均选择同一波形档，温度不是此前共同白偏的必要解释。温度准确性尚未与环境计量对照；不用固定温度、不写校准。

历史无编号照片中深色集中一端、大段接近白色；旧编号图、精确684行编号图、B阶段GC16铺白后下电及C阶段连续HV后的编号图都显示约05–15难逐级区分，足以否定“仅起始GC16白或HV保持即可解决”的假设。官方同机固件通过后发现真正差异：官方关闭PM/DFS，项目开启自动DFS；EPDiy兼容RMT直接用APB默认时钟并绕过IDF RMT驱动自带的PM保护，CPU feeder同样没有事务锁。旧实测30.5–48.5ms/相相对11.090ms波形常量被拉长约3–4倍，导致浅阶过驱到白。

适配层新增CPU/APB max锁后，同页面、同36相、同VCOM/PCLK/温度档的单相恢复为11.090–11.112ms，36相399.327ms。实拍16条中心中位数`48,53,60,68,78,86,91,99,115,121,133,148,156,162,165,169`严格递增，旧05–15并白消失。JPEG不是校准反射率，但时序与同图光学同时恢复，足以完成本轮因果闭环；无需通过gamma、VCOM、频率或waveform修改掩盖问题。

### 连续供电控制：gc16-gray16-labeled-continuous

该入口不是把两个现有串口命令串接：两张1216×684输入在上电前完成长度、指针、重叠和格式转换预检；同一锁内只prepare一次、读取一次ON=1温度，先普通GC16白，再普通GC16编号图，最后只stop一次。第一张失败时不会开始第二张，返回后任何主错/退出错都会锁存并清除参考；成功也只留下最终编号图等待人工验收。相位探针要求72/72完整，容量恰为72，额外相位会报告溢出而不能通过。

这复现的是官方“铺白后保持高压并立即绘图”这一项，不复制其总BSP、固定25°C、NVS/SD初始化或8秒空闲任务，也不改18MHz、80MHz存储、leading-skip、factory VCOM、36相表或gamma。官方8秒是空闲下电规则；本入口没有空闲等待。EPDiy同步绘制内部的永久等待来自固定上游，当前没有可安全取消DMA/renderer的接口，故只承诺正常/错误返回后的立即清理，不承诺硬挂起可由本层超时恢复。

### 离线官方绘图控制：gc16-gray16-vendor

保持原 `gc16-gray16` 全屏无编号布局（16×76×684），而非编号图或官方整页 UI。厂家实际 `epd_fill_rect(i*17)` 在现有 difference_fb 暂存区生成目标，与标准 PhotoFrame 转换后的 front_fb 全长比较；不一致则拒绝、退出并锁存，不调用 HL 绘制。相等后复制厂家绘图目标到 front_fb，并调用厂家实际 `epd_hl_update_screen_from_white`。不增加帧缓冲分配，不改厂家源码。日志 `native_equal=1 from_white=1` 仅表示输入及入口，不证明光学效果。

会话要求 drawn=0，原生后端另要求 untouched_white；只有本启动 clear-white/人工确认/white-confirm 后的首次绘制可走此入口。任何其他图案绘制后均不能把背缓冲重置成假白参考，退出或故障清除资格。原 ID 0–6/位号不变，控制图为 ID 7/位 0x80，只链接到显式显示诊断配置；普通只读 profile 不链接 helper/API。

历史厂家绘图控制阶段直接编译固定`epdiy.c`/`highlevel.c`，逐像素验证真实填充与转换一致，并验证from-white/full在白参考下模式、差分和dirty标志一致；板绑定、IO、renderer/时钟及差分汇编使用替身，所以当时不覆盖LCD/DMA/汇编/电源/波形物理效果。当前PM锁候选另有310/310主机回归与真机证据；产物身份见VALIDATION。

## 便携 API 与内存所有权

`components/read_pico_display/` 不依赖 ESP-IDF、EPDiy 或 PMU IO。没有复制/修改厂家驱动与波形。

- `read_pico_frame_convert`：输入高 nibble 优先、输出低 nibble 优先；支持顺时针 0/90/180/270°，反色只能显式选择。默认路径交换 nibble，不改变灰阶。
- 两端分别提供尺寸、stride、长度；检查零尺寸、stride 不足、算术溢出、旋转后几何、短缓冲与内存重叠。非法输入在修改目标前返回错误。
- 奇数宽度逐行处理；输入未使用 nibble 不当像素，输出未使用 nibble 为白。行 padding 保持原样；不要求末行尾 padding 存在。
- 不分配内存、不就地转换。调用者在返回前持有源图及目标缓冲；源图保持不变。原生 GC16 事务需要 415,872 字节转换缓冲，另有 EPDiy 内部缓冲，后续必须单独测量总预算。

## 刷新契约

`read_pico_refresh_gc16` 是长度明确的便携同步事务。它接收外层提供的 ops：try_acquire/release、prepare、draw_gc16、stop；P2b 原生后端已挂接，诊断执行路径仍不启动它。

流程：独占锁 → VCOM/可用温度来源检查 → 校验及转换 → prepare → 主动温度采样（如配置）→ GC16 → stop → 释放锁。

gate 要求有效 PMU VCOM（500–2500 mV、10 mV 对齐）。未配置 `ops.read_temperature` 时仍要求预验证的有效 0–50°C 温度；配置主动传感器时忽略 gate 的温度字段，在 prepare 成功后同锁采样，错误/越界/未写样本返回独立 TEMPERATURE_FAILED、不 draw，仍 stop/释放锁。Read Pico 配置此回调，因为 SY 温度只在 ON=1 转换；预检仅验证待机 OFF/故障，不将复位值用于温度 gate。外层保证新鲜同 session PMU 与实际板状态；禁止固定 VCOM/25°C 或过期快照，核心不能独立验证时效/模拟电气。

锁失败、VCOM gate 关闭、帧错误不启动电源；旧预验证温度路径无效同样不启动。主动传感器在标准 prepare 通电后采样，失败必须 stop，不是“先验证温度再通电”。prepare/采样/绘制错误和 cleanup_error 分别保留；只有绘制与退出成功才 completed=true，不证明实屏正确。原生采样错误清除参考并锁存，禁止本启动重试。

原生适配层已实现以下约束；主机模拟不代替硬件验收：

- 所有显示/电源入口使用同一把真实锁，不能旁路；BUSY 返回不排队，不是已经实现多任务请求合并。
- prepare 校验电源轨/PGOOD，并确认 PMU 出厂 VCOM；不引入校准写、默认值或总 BSP 初始化副作用。
- draw_gc16 使用厂家原始波形/完整扫描参数，传播 EpdDrawError；不能把 void 返回视为刷新成功，也不能偷偷改成 DU。
- stop 在 prepare 部分失败后也安全；清理失败须锁存硬件未知/故障状态，禁止下一次正常刷新，待明确恢复成功才开 gate。核心释放的是请求锁，不代表硬件已经恢复。
- 绘制失败后不能把失败帧当成已知物理背缓冲；下一次刷新必须采用经验证的恢复路径，保留源图，不以自动刷白掩盖失败。

PhotoFrame 其他板型保留原 void 契约；Read Pico display_manager 使用检查式 API。文件/RGB/流式/灰阶图/清屏失败后释放锁，不发布图片链接、快照或清除 NVS；顺序/随机轮播失败不保存 last_image、不推进索引。`display_manager_rotate_from_storage_checked` 将失败传给新板的 trigger_image_rotation；display_flow 接收原显示入口的错误。旧成功记录被保留，不表示故障后物理屏幕仍完整显示旧图。完整业务 app_main 仍与诊断隔离，Web/SD 真机闭环在 P3。

## 原生后端与电源授权

厂家 epd_board_read_pico 的 init 自建 I2C/IOE、复位触摸和初始化 SY，未直接引用。新板后端借用 HAL I2C0 租约，租约存在时 HAL 拒绝释放总线；所有显示入口按显示锁→递归总线锁顺序串行。IOE 仅更改 MODE/XOE/SY_EN/VCOM_EN，读回核验并保留触摸及输入位；先写安全输出再配置方向，拒绝接管已有通电电源轨。

仅选入固定厂家 EPDiy、E0470 波形、SY 故障解码器及单独编译的原始扫描时序；未引入 Demo/BSP 总初始化、校准 UI、SD 或触摸。当前已部署版本使用16-bit LCD原引脚、18MHz/FULL扫描、原生横向、GC16原波形并关闭leading-skip；12→18MHz由同一solver重算整组时序，实屏几何失败形态基本不变。80MHz Flash/PSRAM保持不变；120MHz/HPM、leading-skip和实际DMA/电气时序仍须分别验收。

`read_pico_epaper_init(true)` 是显式能力入口，须核验实物及运行条件；普通 main 传 false，获准的显示测试 main 仅在命令触发后传 true。上电把 PMU VCOM 配置进 SY 易失性寄存器，应用厂家标准 VLDO/延时/operation；**不写 PMU 校准、ESP NVS 或持久 VCOM**。厂家 AGENTS 禁写与本项目范围的冲突已由用户明确允许标准易失性配置解决；随后另获 factory app-only 只读诊断和受控首次清白授权，不扩展为任意调参、波形改动或完整迁移。固定第三方文件仍原样。

外层 `read_pico_sy_power` 保留厂家启动序列，但补齐原 API 忽略的退出/设备释放错误。SY 寄存器采用 STOP 后读取；PGOOD 最多 30 次轮询，不将负错误值当作高电平；关闭 VCOM/operation/EN 后核验 IOE 和 PGOOD。失败保留原生错误；设备未释放则保留句柄/总线租约，可重复 deinit 清理。

照片刷新前检查新鲜 PMU VCOM 一致性；待机数字核预检发现异常 ON/故障时不启动高压轨。标准上电完成后采样实时 SY 温度（0–50°C），无默认值/额外校准写；采样/绘制/退出错误锁存，本启动不再刷新。厂家 HL 即使出错也会修改 back_fb，因此不把失败帧当成已知物理参考。

## 首次白屏、内存与验收

初始化只将内存 front/back 填白，不宣称物理屏幕全白。`clear_unverified` 的厂家 epd_clear 返回 void，不能报告全部扫描/DMA 错误；其返回 ESP_OK 仅表示已观测电源/退出无错。必须由人确认当前启动会话的实屏白屏，再显式调用 `confirm_white_reference`；没有自动确认路径。

原生 HL 拥有两个 415,872 字节帧、一个 831,744 字节差分缓冲，共 1,663,488 字节 PSRAM，另有 684/608 字节内部 dirty 标记；业务帧另需 415,872 字节。分配失败可清理返回；厂家 renderer/LCD 初始化仍有 assert/abort 路径，64 KiB 最大连续内部块检查不是 OOM 保证。真实剩余内存、图像峰值与 DMA 稳定性必须实测。

## 扫描观察器（本轮单次真机清白通过）

仅 `CONFIG_READ_PICO_DISPLAY_VALIDATION` 链接外层 GNU `--wrap` 注册函数，不修改固定厂家代码。记录只包围一次显式 clear-white：保存并调用原回调一次，保留原参数/返回值；IRAM 回调只读数据并写内部 DRAM 计数，无日志/分配/I2C/延时或自动恢复。原回调在临界区外调用，frame done 可重入注销；结束恢复最后的原回调注册。

固定 clear 为 3×(10 dark + 13 white + 3 no-op)=78 帧。记录注册/完成/逐帧 source 回调数，以及逻辑 680–687 行各 304 字节的首/尾字节。便携分析要求末 4 个有效行匹配各相位 0x55/0xaa/0x00、4 个填充行均 0、首尾相等，无缺行/错核心/孤立/迟到/未完成/溢出；不满足时会话失败锁存，禁止 white-confirm。最多保存 96 帧，超限显式报错。退出 IOE 只读观察先于逐帧打印，清白计时不含打印。

`coverage_complete=1` **仅表示软件观测完整且首尾脉冲符合预期**。预取可能令回调数超过 688；这不是实际送屏的行数。未采样行中间字节，也不观测 DMA 电气完成、CKV/STV、高压轨或可见像素。观察器增加约 4.8 KB 内部静态数据及回调开销，不能宣称完全不影响时序；不得把与旧镜像的差异直接作为根因证明。软件检查通过后仍需本轮人工全白确认。

历史 app-only 部署轮与本轮四角复测前的两次独立清白，均记录 78 帧/每帧 696 次 source 回调/seen=0xff，末 4 个有效行首尾匹配 dark/white/no-op，4 个填充行均 0，全部观测故障计数为 0；各轮退出 input0/out0=0x81、清白含初始化 14.018 秒（不含逐帧打印），分别取得本次启动人工全白确认。部署轮只清白/确认/stop；复测轮另有获准的一张四角 GC16，观察器记录仅包围清白、未记录 GC16 feeder。无连刷/降频或校准写。重复清白的累计效果、观察器时序开销及其他因素均未区分，不宣称黑带根因已解决。

## 受控白屏测试入口

```sh
python build.py --board read_pico --step firmware \
  --read-pico-factory-diagnostic --read-pico-display-validation
```

独立输出 `build-read-pico-display/` / `.cache/sdkconfig.read_pico-display`，固定原 factory 布局，`CONFIG_READ_PICO_DISPLAY_VALIDATION=y`；普通配置显式为 n。编译脚本不烧写，额外 flash/monitor/erase/fullclean 参数仍拒绝。该入口先只读核对布局/PMU/VCOM，然后停在 WAIT_CLEAR_COMMAND；重启不会自动清白。

- `clear-white`：只在本次会话初始阶段允许一次。初始化 EPDiy，再调用未验证的厂家清白及退出观测；成功进入 WAIT_WHITE_CONFIRM，错误锁存，不能正常重试。
- `white-confirm`：只能在等待阶段、且人确认本次启动全白后发送，调用参考确认并进入 REFERENCE_KNOWN；不自动显示 GC16 图案。没有看到实屏时不得发送。
- `status`：只报告会话状态，不读写屏幕或 PMU。
- `stop`：显式释放显示/HAL；清理失败保留错误与租约，只有另一次显式 stop 可重试清理，成功后本会话终止。

48 字节有界 ASCII 解析，控制字节/溢出整行丢弃，不执行合法前缀。`scripts/read_pico_display_console.py` 在固定 IDF Python 下连接 USB；默认不复位，只在 `--reset` 时显式复位，启动不发命令，断连不重连/重发。日志私有保存；确认期间保持同一次 ESP 启动，不重新烧写/复位。实际串口状态与人工结果是后续动作依据，不沿用上一会话的白屏参考。
