## 创建与发布

`read_pico_background` 包含四类业务与PERIODIC第五固定角色的SDK适配，不是新的相册/产品状态系统。每个启动只有一份永久槽位，逐次检查 `xTaskCreate == pdPASS`，保留原任务名称、优先级和栈字节数。固定 ESP-IDF 的栈大小单位为字节，不按 vanilla FreeRTOS 的 word 数理解。

创建后的包装任务先等待，不能立即调用原业务函数。电源初始化创建需要的 sleep 和 rotation；main创建button、连接超时时创建late Wi-Fi，periodic初始化创建第五worker。全部必需角色已创建才调用检查式 HTTP ready 发布，然后原子放行任务。创建/发布错误不打印该分支启动成功；既有任务收到取消，自行退出，不跨任务强删。重复创建、重复发布和取消后的重建均拒绝，槽位在本次启动不复用。

Read Pico main 包装原启动函数；启动返回且门禁未活动时请求取消等待任务，最多2秒确认回调返回后才尝试关闭仍ready的本角色HTTP；退出未确认则不继续HTTP清理。电源、其后的 OTA/相册及配网初始化错误改检查式返回，避免这些分支以 panic 重启代替任务错误报告。此前其他初始化、周期 timer、mDNS、显示/SD 和 SDK 内部对象并不因此自动销毁。HTTP startup 失败还检查本角色 stop；底层 HTTP stop 仍可能无界等待，不把它当有界整机清理。

PMU睡眠门禁不变。四处条件提前睡眠在Read Pico上返回时不再继续轮播；CLEAR和timer/rotate唤醒流程返回时不再落入普通冷启动。可能已进行的唤醒工作不回滚，wake配置窗口原有HTTP发布行为不是完整后台启动；窗口/失败返回后只按上述检查式退出，不宣称实机睡醒通过。

## 合作取消

原业务函数由包装任务调用，Read Pico 分支须释放本函数资源后 **return**，只有包装任务调用 `vTaskDelete(NULL)`。定时和按键在下一次安全循环边界检查任务门禁及 HTTP ready；late Wi-Fi 不再永久等待 event bit，改 100ms 有界等待并检查事件组、取消和当前连接。在线启动在入口及延迟 OTA 前再次检查门禁。旧板保留原创建、自删除及等待行为。

联网恢复/启动返回先关闭周期接纳，再取消受管角色并最多等待2秒确认其他回调已返回，确认timer退出后才清理无线/HTTP；只豁免确实正在执行包装回调的当前自有任务。创建/发布控制忙、退出超时都不继续改变无线或关闭 HTTP。正常确认后才沿用原恢复流程；单纯调用 cancel 不宣称退出已确认，超时不强删、不自动复用，可再显式核对。

等待 API 只允许有限预算（至多 5 秒），检查 tick 回绕；确认不等于 FreeRTOS idle 已回收 TCB/栈，也不等于周期 timer、SNTP、HTTP 请求、SDK 默认事件任务或完整资源已退出。取消不是中断已开始的图像处理、HA、文件/NVS/SDK 操作，不能回滚它们。发布与取消竞争时不重新激活，外部 HTTP ready 仍由 main 负责撤销。
